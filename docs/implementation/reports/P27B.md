## 2. Pre-edit cleaning profile (P27B-A, reference orchestration, 5000 mixed docs, 12.8 MiB)

779 docs/s, 2.00 MiB/s in, wall 6.42 s. Per-stage share of wall: language
25.0%, repetition 16.3%, noise 10.8%, PII 8.3%, normalization 2.0%,
boilerplate 1.7%, HTML 1.2%, length 0.7%; parse 0.09 s, construct ~0.0 s,
serialize 0.05 s. Clean-prose 5k: 681 docs/s (language 29%, noise 19%,
repetition 13%, PII 11%). Large-doc 500×50 KB: 28 docs/s, 1.86 MiB/s

inside stage times (~2 s for 2856 rejections: one open/write/close per

per-doc orchestration negligible, quarantine I/O pathological when noisy.

## 3. Exact optimizations implemented

- **Compile-once (F):** repetition char-run pattern compiled per filter
  instance (was per document); language word pattern module-level;
  pipeline built once per worker process (pool initializer + keyed lazy
  cache for in-process runs).
- **Shared lazy features (G):** `TextFeatures` shares `split`/`splitlines`/
  one-pass char stats across stages observing the same text object; new
  string object after any mutation = automatic invalidation (strong ref
  keys identity). Consumers read-only; released per document.
- **Fused scans (H):** language latin/alpha and noise non-ws/symbol/digit
  tallies each computed in one pass with exactly the reference integers
  (identical ratios, reason strings, thresholds).
- **Repetition (I):** compile-once, single `splitlines`, generator-based
  5-tuple Counter (identical multiset), Markdown structural exceptions
  untouched.
- **PII hint gate (K):** one combined presence scan over the seven
  non-email patterns (inline flags re-scoped so `AKIA` stays
  case-sensitive); miss skips seven scans, hit runs the unchanged detailed
  path. Email scan always runs (reserved counts feed metrics). A 100+
  assertion test proves hint-miss ⟺ no-detailed-match.
- **Copy shortcut (P):** `create_transformed_copy` reuses hash/byte count
  when text is unchanged (definitionally identical values); log entry
  still appended.
- **Buffered quarantine (O/E):** entries via shared pure
  `build_quarantine_entry` (reference manager refactored onto it,
  byte-identical lines); 1 MiB buffered sink, one fsync per unit instead
  of per-record open/close (~17×: 2.0 s → 0.12 s on mixed-5k).
- **Accepted output (P):** `StreamingJsonlWriter` single traversal
  (hash/count free); no dict→JSON→dict chains (none existed; verified).
- **No-ops preserved:** stage order, short-circuit, reason ordering,
  thresholds, metrics shapes, secret omission, preview rules.

## 4. Sharded-input/output architecture

Input: single `.jsonl` (newline-aligned range split, C-speed scan, exact
blank-aware doc counts + physical line offsets for identical errors),
verified P27A manifest dir (full `verify_manifest` before planning; one
unit per shard), plain dir (legacy per-file fan-in), Parquet (single
unit). Nothing is ever concatenated into a giant temp first. Output:
legacy `documents.jsonl` (atomic replace) or deterministic target-sized
`shard-%05d.jsonl` + `clean-manifest.json` (P27A primitives, manifest
last, re-verified); quarantine single `quarantine.jsonl` with reference
caps enforced in global order, optionally resharded +
`quarantine-manifest.json`; `cleaning_summary.json` (reference shape),
`cleaning_throughput.json` (telemetry), quality reports, Parquet view for
legacy output only.

## 5. Parallelism strategy

Process-level (GIL-bound Python confirmed by profile): one future per
worker over static round-robin unit chunks (measured: finer tasks cost
more in pickling/scheduling than dynamic balance repays). Workers receive
paths + byte ranges only — zero document pickling. Bounded in-flight =
`max_workers`. Results consumed in unit index order; merge adds integers
in order, reasons keep global first-encounter order, yields recomputed by
the reference formula. Any worker exception (or cap-ceiling position)
aborts before publication: staging removed, no manifest, no summary.
`workers=1` runs the same worker function in-process. Default: 4 workers,
16 MiB input units.

## 13. Single-file vs sharded equivalence

Legacy accepted bytes == sharded stream record-for-record; single vs

manifests + aggregates as single-file input; workers 1/2/4 agree;
output targets 8 KiB/64 KiB/512 KiB preserve the stream; batch

line numbers identical to the reference.

## 14. Exact remaining bottleneck

Per-document Python in language (word regex + lower + stop-word scan)
and repetition (5-gram tuple construction/counting), plus PII's eight
regex passes on dirty text; at scale, spawn overhead (~2–3 s/run) and
single-threaded parent assembly cap efficiency at ~55%/worker at w8
(3.4–4.4× observed). Disk is not the limit (I/O phases < 5% of wall).

## 15. Dedup fingerprint precompute (P27B-T)

Not implemented — correctly so. Audit found P28's exact dedup already
keys on `doc.clean_hash` (sha256 of final cleaned text), which
`create_transformed_copy` computes during serialization anyway. The
fingerprint is already free; any sidecar would duplicate it. Verified in
`src/xlm/data/dedup/engine.py` (`clean_hash` identity + `stable_hash64`
of it).

## 16. Recommended shard targets for cleaning

Input units 16 MiB (CLI default; 8+ balanced units per 128 MiB for ≤8
workers; below ~1 MiB per-unit fsync/tmp overhead dominates — measured
7 s penalty at 64 KiB units on 5k docs). Accepted output 64 MiB
(uniform with P27A adapt; cleaning yield shrinks bytes). Quarantine
16 MiB when sharded (it tracks input scale on noisy sources).

## 17. Concrete recommendation for P28

Consume `clean_hash` directly as the exact-dedup identity — no cleaning
sidecar needed. For further cleaning speed: attack per-document Python
(below), not I/O or orchestration: (a) language stop-word scan over the
already-shared word list with early admission counting that preserves
exact counts (metrics need full counts, so gains are limited to the
regex+lower step); (b) repetition 5-gram counting with interned string
keys only if proven collision-free (tuple equality is the safety
property — do not approximate); (c) process-pool reuse across CLI
invocations is out of scope (one-shot jobs). Do not fuse stages
cosmetically, do not reorder filters, do not batch language inference
without identical-results proof.

## Open limitations

- `recorded_at` and all duration/elapsed fields are run-dependent by
  nature and excluded from equivalence by design.
- `adopt`-style resume is not wired for clean; crashed runs rerun
  (fail-closed, deterministic).
- Raw (non-canonical) single-file input keeps the original orchestration;
  only canonical input uses the engine.
- Sharded output carries no Parquet view; legacy output does.
- Windows spawn costs ~2–3 s per run; tiny jobs (<1 MiB) gain nothing
  from workers > 1.
