## 3. Implemented Architecture

### 3.1 `src/xlm/data/dedup/`

| Module | Responsibility |
|---|---|
| `matchview.py` | Versioned aggressive match view (NFKC, case folding, punctuation removal, whitespace collapse) used **only** for duplicate and exclusion detection, never written back into canonical text (C03) |
| `minhash.py` | Deterministic word shingling, MinHash signatures and banded LSH keys. Permutation coefficients derive from a frozen seed; shingles hash with BLAKE2b, never Python's randomized `hash` (C02) |
| `index.py` | `PartitionedKeyIndex`: append-only, disk-backed multimap sharded by a stable key hash. Read back one partition at a time; deliberately offers no per-key lookup, which would invite the RAM-resident dictionary C05 forbids |
| `lineage.py` | Lineage keys from explicit IDs, synthetic seeds, conversation IDs, book IDs, document/page IDs, and canonicalized URLs (scheme, `www.`, fragment, trailing slash and tracking parameters stripped) |
| `clusters.py` | Union-find with deterministic tie-breaks, content-derived cluster IDs, and the frozen survivor rule |
| `engine.py` | Two-pass streaming orchestration: exact pass, then bounded near-duplicate verification |

**Frozen survivor rule v1**, applied in order: largest canonical UTF-8 byte count →
lexicographically smallest `source_id` → lexicographically smallest `doc_id`. No step
consults arrival order.

**Bounded verification.** Two explicit bounds keep candidate generation sub-quadratic:
an LSH bucket larger than `max_bucket_size` is *counted as oversized and skipped*
rather than expanded pairwise, and each document contributes at most
`max_candidates_per_document` pairs. Both are reported in `DedupStats`.

**Lineage is not duplication.** Lineage groups are deliberately *not* unioned into the
duplicate forest. A book's chapters are a family, not copies; folding them together
would silently delete most of a book. Lineage instead feeds split-safe co-assignment.
This was a defect in the first draft of the engine, caught by a fixture of three
genuinely distinct chapters, and is now pinned by
`test_lineage_families_are_reported_but_never_deduplicated_away`.

### 3.2 `src/xlm/data/pools/`

- `splits.py` — split groups are the connected components of duplicate clusters
  combined with lineage families. Groups are ordered by a content-derived keyed hash
  of the frozen seed and assigned **whole**, so assignment cannot depend on input
  order and a group is never partially held out. Diagnostic validation fills first,
  then audit, then training. The quick subset is a prefix of the same ordering, so it
  is nested inside the diagnostic set by construction rather than by a later filter.
  Defaults follow C05: 50 MB diagnostic validation, 5 MB quick subset.
- `freeze.py` — `PoolFreeze` binds pool identity to the dedup identity, split policy
  identity and a membership digest. `detect_bridge_duplicates` compares a frozen pool
  against a newer dedup result and reports clusters that bridge formerly separate
  groups; only a bridge **crossing a split boundary** invalidates. `supersede_pool`
  creates a new lineage without editing the old freeze's membership, so affected
  comparisons remain identifiable.

### 3.3 `src/xlm/data/exclusion/`

- `benchmark.py` — full-example hashing (prompt plus **every** candidate answer, not
  just a gold one) and informative-span matching. Spans are drawn per segment
  (prompt, and prompt-plus-each-answer) rather than from the concatenated rendering;
  a span straddling two unrelated candidate answers is a concatenation artefact that
  could never appear in a contaminated document. Spans occurring in more than
  `max_corpus_span_frequency` corpus documents are suppressed as common English.
- `receipt.py` — `FinalExclusionReceipt` binds corpus input digest, exclusion policy
  identity, index identity, output membership digest and issuer. HMAC signing
  establishes integrity and authenticity. `verify_receipt` under `protected` policy
  rejects malformed, inconsistent, unsigned, untrusted-issuer, tampered, wrong-mode
  and corpus-unbound receipts, and rejects any receipt carrying forbidden protected
  fields. `issue_development_receipt` is explicitly `mode="development"` and can
  never satisfy a protected check.

## 7. Documented Limits

**Hash collisions.** Clean identity uses SHA-256, treated as collision-free at corpus
scale. Shingle hashing uses 64-bit BLAKE2b, which is *not* collision-free at that
scale: a collision could add a spurious shingle agreement. Its effect is bounded —
one collision perturbs a single MinHash position out of 128 and cannot by itself carry
a pair across the similarity threshold. `detect_hash_collision_risk` surfaces the risk
rather than asserting its absence.

**Near-duplicate false positives and negatives.** MinHash estimates Jaccard
similarity; it does not compute it. At 128 permutations the standard error of the
estimate is roughly 0.09, so pairs near the 0.8 threshold may fall on either side.
Banding adds its own profile: a pair below threshold can still share a band, and a
pair above it can be missed if no band matches. Oversized buckets are skipped
entirely, which is a deliberate recall sacrifice for a bounded cost, and is counted.
**No precision or recall figure is claimed**, because no labeled duplicate audit
sample was collected.

**Contamination detection cannot prove absence.** Exact and informative-span matching
catches verbatim and lightly embedded reproduction. It does not catch paraphrase —
demonstrated directly by `test_paraphrase_is_acknowledged_as_undetected`, which asserts
the paraphrase is *missed* and that the report says so. Absence of hits is not evidence
of an uncontaminated corpus.

**The receipt interface is not isolation.** HMAC verification establishes integrity
and issuer authenticity. It is not confidentiality and not an OS boundary.
`assert_no_protected_access` is an in-process guard rail whose own docstring states it
is not an OS security boundary. Per EVALUATION_POLICY, real isolation requires a
separate OS identity, and this environment remains **nonsealed**.

**Development mode only.** Every benchmark example in the tests is authored synthetic
fixture data. No real benchmark split was read, no protected final data was accessed,
and no sealed-final claim is made anywhere in this milestone.
