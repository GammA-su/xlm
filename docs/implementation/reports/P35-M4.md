## 1. Pre-change comparison audit (written before any product edit)

Read from the code at `9f57869`. Paths are under `src/xlm/`.

| # | Question | Finding |
|---|---|---|
| 1 | Existing comparison tracks | `comparison/tracks.py` (P17, `TRACK_CONTRACT_VERSION = "1"`): six `TrackRule`s — `architecture`, `objective`, `optimizer`, `tokenizer`, `data-mixture`, `unconstrained-system` — each a `fixed`/`allowed` tuple over 22 `REQUIRED_FIELDS`. Two-way classification only (fixed vs allowed); **no "recorded, may differ" class** and no declared-intervention list: an allowed field may differ without being declared. `unconstrained-system` allows everything except precision. **No microbatch track.** The `data-mixture` track *fixes* `data_seed` and allows `canonical_bytes`/`init_seeds`. `init_seeds` is an allowed difference on every track, i.e. seed mismatches inside a "pair" are not a violation. |
| 2 | Bootstrap behavior | `comparison/bootstrap.py` (`BOOTSTRAP_VERSION = "2"`): paired **item/cluster** percentile bootstrap (`cluster_bootstrap_difference`, `suite_bootstrap`), `random.Random(analysis_seed)`, default analysis seed 20260918, 1,000 resamples. It quantifies uncertainty over benchmark items within one run pair. `seed_spread` reports min/mean/max of per-seed differences and returns `None` for one seed. Coverage records are admission-checked (`SuiteCoverage.complete`, `research_eligible`). |
| 3 | Learning-curve comparison | `comparison/curves.py`: `LearningCurve` (x = `x_tokens`), `crossing_at_target` by linear interpolation only, `compute_to_target`, `compare_compute_to_target`. **No curve area**, no requirement that two curves share a target grid or range, no endpoint check. |
| 4 | Promotion rules | `comparison/promotion.py` (`GATE_RULES_VERSION = "1"`, `PROMOTION_VERSION = "1"`): `PromotionGates(min_suite_delta=1.0, min_compute_saving=0.10, min_seeds=2, require_ci_excludes_zero=True, max_task_regression=0.5)`. Promotes on **suite index delta ≥ +1 point or ≥10% compute saving**, CI excludes zero, and ≥2 seeds per arm. Task regressions become *warnings*. `next_size_draft` emits a 150m/300m draft. These are the P17 policy defaults the contract (§A "Existing comparison") calls **old policy, not P35 confirmation**. |
| 5 | Minimum-seed logic | `evaluate_promotion`: `n_seeds_baseline >= min_seeds and n_seeds_candidate >= min_seeds` (default 2). `promote_command` counts `len(compared["seeds"]["baseline"])`, i.e. the number of evidence files passed. There is no scale-stage sample size (5/3/3), no fresh/exploratory distinction and no provisional state. |
| 6 | Headline metric selection | `xlm compare`: the headline is the **four-task suite index** (BLiMP/ARC-Easy/HellaSwag/PIQA) of the numerically smallest `(init_seed, data_seed)` pair (`PRIMARY_SELECTION_POLICY = "numeric_lexicographic_min_v1"`). LM CE/BPB is never the headline; no metric direction is declared (the suite index is implicitly higher-is-better). |
| 7 | Failed/missing runs | `xlm compare` accepts only evidence files that exist; failed runs cannot be represented at all, so they are silently absent. Missing partners are refused (`pair_seed_evidence`). `collect_campaign_report` notes "N of M trials have no executed run". Nothing reports failed attempts next to a comparison. |
| 8 | Run identity | `ComparisonRun(run_id, fields)`; `run_id` is `evidence.identity.fingerprint` or the synthetic `unidentified-seed-init{i}-data{d}`. Facts come from a P16 plan (`resolved_config`) plus P15 evidence plus an operator `--facts-*` JSON that **overrides inferred values** (`extra`). No execution hash, checkpoint id or evaluation receipt is bound. |
| 9 | Fields inspected | data: `mixture_id`, `mixture_weights`, `canonical_bytes`, `packing`, `data_seed` — yes; tokenizer: `tokenizer_hash`, `vocab_size` — yes; **LR/schedule: no** (only `horizon_kind` from the plan); seed: `init_seeds`, `data_seed` (no `training_seed`); **runtime: no**; **attention: no**; precision: yes; **microbatch: no**; **global batch: no**. Also no LR policy, optimizer hyperparameters (only `optimizer_id`/`tuning_allowance`), code/environment, evaluation inventory or budget completion. |
| 10 | Same-seed reruns as replicates | `pair_seed_evidence` refuses a duplicate `(init_seed, data_seed)` within one arm, so two files of the same seed cannot both be passed. But the replicate key omits `training_seed`/order, and `promote_command` counts files, so a second seed label with otherwise identical tuple is indistinguishable from a real replicate. There is no replicate identity separate from an attempt. |
| 11 | Paired comparisons | Yes, at the item level (`align_paired_items`) and at the seed-pair level (`pair_seed_evidence` keyed by `(init_seed, data_seed)`). |
| 12 | Student-t seed intervals | **None.** No between-seed mean/SD/t-interval exists anywhere; `seed_spread` is min/mean/max only. |
| 13 | Multiplicity | Only a free-text `multiplicity_note` ("decision support only: N comparison(s) … examined"). No family id/size, no adjusted confidence level. |
| 14 | Missing benchmark coverage | `suite_bootstrap` refuses missing tasks and incomplete/legacy coverage (`BootstrapError`); `compute_four_task_index` withholds the index. Reports render missing values as `n/a`. M2 search-tier evidence reports `None` (PARTIAL) for truncated coverage. |
| 15 | Versioning of comparison records | `xlm compare` output carries `comparison_version: 1`, `bootstrap_version: "2"`, `primary_selection_policy`; `promote_command` refuses outputs with another bootstrap version/policy. Promotion decisions carry `gate_version: "1"` and a fingerprint. Tracks have `TRACK_CONTRACT_VERSION = "1"` but the output does not record it. |

Other seams the design depends on (read from code):

- **Canonical serialization**: `artifacts/manifest.py::canonical_json` / `identity_digest`
  (sorted keys, no NaN, bounded) — used for every M1–M3 identity. M4 hashes with it.
- **Frozen execution evidence**: a science-v1 frozen checkpoint holds
  `execution.json` = `{envelope, plan_hash}`; the envelope binds the resolved config
  (model, data incl. normalized mixture recipe, objective, optimizer, training incl.
  `science_version`/`lr_policy`/`training_seed`/`runtime`/`microbatch_sequences`/
  `global_batch_valid_targets`/budget/schedule/precision/producer), `bindings`
  (data input hash, tokenizer identity/fingerprint, component keys/serializers),
  `code_hash`, `dependency_hash`, installed `environment`, `runtime_policy` and
  `execution_hash`. `validate_envelope` recomputes the hash.
- **M1 `science.json`**: policy identity, `train_start_rng` receipt, LR receipts
  `[step, committed_before, valid_targets, schedule_counter, lr_used]` (these give the
  exact update boundaries), runtime receipts (`device`, `device_name`, `torch`,
  observed attention operators and flags).
- **M2 evaluation ledger** in `science.json` + immutable attempt artifacts
  (`evaluations` kind): per event `planned_threshold`, `actual_committed_targets`,
  status, `canonical_attempt` (`first_complete_attempt_v1`), outcome records with
  `metrics` (`equal_domain_text_ce_nats_per_token`, micro CE/BPB, per-domain), `coverage`,
  `evaluator` identity, `model_state`, `receipt_identity`.
- **M3 checkpoint ledger** in `science.json`: per publication the planned thresholds,
  actual C, step, `model_state_digest`, `data_cursor_digest`, artifact id and
  verified manifest SHA-256; milestone `checkpoint@0` binds the initial weights digest.
- **Data exposure**: `data_state.json` (committed batcher state) holds
  `mixture_identity`, `exposure_identity`, `committed_valid_targets`, the chained
  per-target `trace_digest` (source, doc, lineage, token offset, label, byte span,
  epoch for every committed target, in order) and scheduler per-source counters
  (valid/repeated/content/EOS targets, documents, bytes, epoch, cursor).
- **Reports**: `reports/render.py` (`to_json`, `metrics_to_csv`, `escape_markdown_text`,
  `escape_html_text`, `n/a` for missing), `reports/collect.py` (`strip_protected`).
- **CLI**: `xlm compare`/`xlm promote` (P17) and `xlm experiment plan|validate|authorize|submit`
  (P16/M3). The handoff's `xlm experiment compare|report` do not exist yet.
- **Statistics libraries**: no statistical dependency is in the base/dev lock.
  `scipy` appears in `uv.lock` only transitively under the `eval` extra (lm-eval), so
  product code cannot rely on it.

Conclusion: the existing P17 machinery is a **legacy, non-P35** comparison stack.
It is not P35 compliant (headline suite index of one seed pair, no t interval, no
declared intervention, no LR/runtime/batch fields, no margins, no scale-stage sample
size, no multiplicity family). M4 therefore adds a separately versioned science-v1
stack and leaves P17 behavior and records unchanged.
