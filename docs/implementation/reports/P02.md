## 2. Implemented Architecture & Components

### 2.1 Canonical Normalization & Strict Decoding (`src/xlm/data/normalization.py`)
- **`canonical_normalize`**: Idempotent Unicode Normalization Form C (`unicodedata.normalize('NFC', text)`), unified `\n` newlines, zero deletion or alteration of non-ASCII characters, whitespace, casing, mathematical formulas, or emoji.
- **`decode_utf8_strict`**: Strict decoding raising explicit `UnicodeDecodeError` on invalid or truncated UTF-8 byte sequences.
- **`compute_sha256`**: Deterministic cryptographic hash function over UTF-8 byte sequences.

### 2.2 Local Adapters (`src/xlm/data/adapters/`)
- **`TextAdapter` (`src/xlm/data/adapters/text.py`)**:
  - Ingests individual text files or directories of text files in deterministic lexicographic order.
  - Strictly enforces bounded file size (`max_file_size_bytes`).
  - Produces `CanonicalDocument` with source attribution, document IDs, raw hash, clean hash, byte length, and character length.
- **`JsonlAdapter` (`src/xlm/data/adapters/jsonl.py`)**:
  - Ingests JSON Lines files with duplicate JSON key rejection via `_pairs_hook_reject_duplicates`.
  - Validates required fields (`id`, `text`, `source_id`), enforces strict string types (rejecting numeric or object types), and verifies canonical split assignment (`train`, `diagnostic_val`, `benchmark_val`, `dev`).
  - Enforces uniqueness of document IDs across the entire source.

### 2.3 Canonical Dataset IO (`src/xlm/data/canonical_io.py`)
- **`CanonicalDatasetWriter`**: Serializes normalized documents into partitioned JSONL or Apache Parquet files with deterministic `newline="\n"` across platforms.
- **`CanonicalDatasetReader`**: Reads documents with verification against source metadata and schema checks.
- **`create_dataset_manifest`**: Assembles canonical dataset metadata and file manifests for publication to the immutable artifact store.

### 2.4 Token Shards & Manifest Contracts (`src/xlm/data/tokens.py`)
- **`DocumentTokenRecord`**: Lightweight record storing document IDs, token ID arrays, and true UTF-8 half-open byte spans.
- **`TokenShardWriter`**:
  - Encodes token streams into binary buffers with dynamic type selection: `uint16` if `vocab_size <= 65536`, else `uint32`.
  - Computes cryptographic SHA-256 checksums over raw binary payloads.
  - Emits `TokenShardManifest` strictly conforming to XLM contract C07.
- **`TokenShardReader`**: Reads token shard payloads and validates byte lengths, dtypes, and SHA-256 integrity against corruptions.

### 2.5 Tokenizer Subsystem (`src/xlm/tokenizers/`)
- **`BaseTokenizer` (`src/xlm/tokenizers/base.py`)**:
  - Abstract base class defining `encode`, `decode`, `encode_with_offsets`, `batch_encode`, `save`, `load`, and ID boundary validations.
  - Declares canonical special token IDs: `<pad>=0`, `<bos>=1`, `<eos>=2`, `<unk>=3`.
  - Strict out-of-bounds check rejecting negative IDs or IDs $\ge \text{vocab\_size}$.
- **`ByteTokenizer` (`src/xlm/tokenizers/byte.py`)**:
  - Zero-training deterministic byte tokenizer fixture.
  - Vocabulary size: 260 (IDs 0..3 reserved for special tokens, IDs 4..259 representing bytes `0x00`..`0xFF`).
  - 100% reversible, emitting exact single-byte spans `[i, i+1)`.
- **`ByteLevelBPETokenizer` (`src/xlm/tokenizers/bpe.py`)**:
  - Wraps Hugging Face `tokenizers` byte-level BPE implementation.
  - Pipeline configuration: initial alphabet `ByteLevel.alphabet()`, `ByteLevelDecoder`, `add_prefix_space=False`, `use_regex=True`.
  - **Literal Special-Token Protection**: Special tokens are stored in the BPE model vocabulary at indices 0..3, but explicitly excluded from `added_tokens = []`. Standalone, adjacent, repeated, whitespace-surrounded, or code-embedded literal strings (such as `"<eos>"`) are tokenized as normal text bytes and NEVER emit control IDs 0..3.
  - **True Half-Open UTF-8 Byte Spans**: Derived directly from token byte payloads via the GPT-2 byte mapping (`_U2B`), accumulating byte lengths without gaps or overlaps, correctly handling multibyte characters and emoji split across BPE merges.
  - **Train-Only Fitting Enforcement**: Iterates over input canonical datasets, strictly filtering documents where `doc.split == "train"`. Rejects non-train documents and enforces a minimum vocabulary size of 260.

### 2.6 Registries & CLI Commands
- Registered `byte_fixture` and `bpe` under the `tokenizers` component registry.
- Registered `text` and `jsonl` under the `source_adapters` component registry.
- **CLI Commands**:
  - `xlm data import-local`: Imports local files/directories and publishes canonical dataset artifacts.
  - `xlm tokenizer train`: Fits byte-level BPE on training data and publishes tokenizer artifacts.
  - `xlm tokenizer inspect`: Displays tokenizer configuration, special tokens, and training input hashes.
  - `xlm tokenizer encode`: Encodes arbitrary text and verifies reconstruction.
  - `xlm tokenizer verify`: Runs 9 automated verification tests against a saved tokenizer artifact.
