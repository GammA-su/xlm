## 3. Changes Made in This Session

### 3.1 Genuine streaming pipeline (`src/xlm/data/cleaning/pipeline.py`)
- `run_stream` now returns a generator (`_iterate`) plus a `PipelineExecutionSummary`
  that the generator populates **in place** as it is consumed. No accepted document
  is retained by the pipeline; at most one record is live per step.
- Added `PipelineExecutionSummary.completed`, so a partially consumed run cannot be
  mistaken for a finished one. Yield ratios are recomputed incrementally via
  `_refresh_yields`.
- Corrected the class docstring, which previously asserted a memory property the
  implementation did not have.

### 3.2 Bounded-memory canonical IO (`src/xlm/data/canonical_io.py`)
- Added an explicit Parquet schema (`_parquet_schema`) plus `_flatten_record` /
  `_inflate_record` helpers, so streamed row groups cannot drift in type between
  chunks the way per-chunk inference can.
- Added `write_parquet_stream(..., row_group_size=512)`, buffering at most one row
  group at a time. `write_parquet` now delegates to it.
- `read_parquet` streams via `pq.ParquetFile(...).iter_batches(batch_size=...)`
  instead of loading the whole table.
- Added `read_shards(directory)`, which streams **every** `.parquet` and `.jsonl`
  shard in stable sorted order, one file open at a time.

### 3.3 CLI repair (`src/xlm/cli/data_cmd.py`)
- Directory input now uses `read_shards`, so no shard is silently dropped.
- Accepted records stream straight to JSONL; the Parquet view is produced by
  re-reading that JSONL shard, keeping the second write bounded as well.
- A Parquet failure is now surfaced instead of swallowed; absence of `pyarrow` is
  reported explicitly rather than passing silently.
- Fixed the `publish_artifact` call (`kind=`, plus real `producer_code_hash` and
  `dependency_hash`), and gated publication on `summary.completed`.
- Moved `json` / `itertools` / `Iterator` to module-level imports.

### 3.4 Quarantine retention and access controls (`src/xlm/data/cleaning/quarantine.py`)
- New `QuarantinePolicy` (strict Pydantic model): `max_records`,
  `max_quarantine_bytes`, `max_preview_chars`, `retention_days` (nullable),
  `store_previews`, `owner_only_permissions`. Existing keyword arguments still work.
- Every entry now carries `recorded_at`.
- `purge_expired(now=None)` enforces the retention window and returns the number of
  records removed. Entries with an absent or unparsable timestamp are **kept**, so a
  malformed record cannot quietly destroy an audit trail.
- `store_previews=False` withholds the preview for every rejection, not just
  secret-bearing ones. Secret rejections remain metadata-only regardless.

### 3.5 Artifact lookup repair (`src/xlm/cli/artifact_cmd.py`)
- `_resolve_artifact_dir` now enumerates the kind directories actually present in
  the store, skipping bookkeeping directories (`_INTERNAL_DIRS`). This restores
  inspect/verify by ID for `clean_dataset` and, incidentally, for the P07/P08
  `probe_evidence` and `raw_dataset` artifacts that were also unreachable.

### 3.6 Honest tests
- `test_base_environment_zero_torch_isolation` rewritten to probe a **fresh
  interpreter** via `subprocess`, since an in-process `sys.modules` check is vacuous
  once any other test has imported torch.
- Removed the dead `already_normalized` variable and replaced its misleading comment
  with a pointer to where idempotence is actually guaranteed and tested.

### 3.7 Multi-shard fixture corpus (`fixtures/cleaning/shards/`)
Six authored JSONL shards, 60 documents, 19,740 canonical UTF-8 bytes. Each shard
plants documents that must survive (prose, mathematical notation, indented code, and
short high-density educational text below the prose byte floor) and documents that
must be rejected (a 40-line repetition loop, and a bearer credential long enough to
reach the secret filter). Entirely synthetic; no acquired or live data.

### 4.1 Negative control for the bounded-memory test

The bounded-memory assertion was validated by deliberately reintroducing the
accumulating implementation (`iter(list(self._iterate(...)))`) and confirming the
suite fails, then restoring the streaming version and confirming it passes.

The first version of that test checked retention **after** stream exhaustion and did
**not** fail the negative control — CPython's list iterator drops its backing list
once exhausted, so a fully materialized run looks clean at the end while still having
held the whole corpus at its peak. The test was rewritten to probe mid-stream. Under
the negative control, 3 tests now fail; on the restored implementation, all 11 pass.


## 8. Limitations and Honest Scope Statements

- **Fixture only.** Every number in §6 comes from a 60-document authored fixture. It
  is not a yield estimate for any real source, and no live acquisition ran here.
- **No classification precision claim.** The language and educational-density
  filters are declared heuristics. No labeled audit sample was collected, so no
  precision or recall figure is claimed. Optional pinned classifier plugins remain a
  blocked capability when weights are absent — by design, rather than emitting a
  fabricated English confidence.
- **PII detection is not a certification.** Pattern-based secret/PII detection
  reduces exposure; it does not establish that a corpus is free of personal
  information (C03).
- **The educational-density exemption is a heuristic.** Short prose without
  mathematical or code markers is still rejected by the configured byte floor. That
  is the declared per-domain threshold behaviour, not a defect — but it does mean
  "short high-density educational text is preserved" holds for the declared
  heuristic's notion of density, not for all short valuable text.
- **Bounded memory is demonstrated over 6 shards / 60 documents**, which is enough to
  distinguish streaming from accumulation but is not a large-corpus performance
  measurement.
- No deduplication, split assignment or benchmark exclusion is implemented here;
  those are P10 and are deliberately out of scope.
