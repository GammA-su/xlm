Training CE is the objective (`objectives/cross_entropy.py`) and counts EOS targets. |
| 3 | Sufficient statistics used | Token-summed NLL: yes. RNG: native scoring consumes none in eval mode, but the harness path reseeds all global RNGs (row 6). Gradients: `no_grad`, none created. Optimizer/cursor: never passed to evaluators; the CLI scores a checkpoint in another process. **Model buffers: `RotaryEmbedding.forward` rebuilds its non-persistent `cos/sin` caches, and its `max_position_embeddings` attribute, whenever a position id reaches the cache length (initially `context_length`). Consequences for the design: a declared cadence proves nothing (row 10);
in-memory scoring of the live training model is unsafe because of the RoPE

receipt (row 13); and the search tier needs a BLiMP partition check (row 15).

## 2. What was built (science-v1 only; legacy untouched)

| Module | Role |
|---|---|
| `evaluation/cadence.py` | Planner. Tiers `quick_lm`, `full_lm`, `search_benchmark`, `endpoint_confirmation`. §K tables `pilot_32m`, `screen_128m`, `full_1b` transcribed verbatim and bound to their budgets; non-research `authored_fixture` for smokes. Confirmation exists only in `full_1b` and only when `confirmation_registered`. Fork re-origin records excluded parent thresholds. |
| `evaluation/receipts.py` | Ledger in `science.json` (only when a cadence exists, so M1 files stay byte-identical). Statuses `planned/due/running/complete/partial/failed/interrupted`. Attempts are immutable `started`/`outcome` artifacts (kind `evaluations`) in the existing `ArtifactStore`. Canonical rule `first_complete_attempt_v1`; retry `retry_on_restart_v1`, at most 3 attempts per lineage. Completeness fails on any non-complete event. |
| `evaluation/lm_validation.py` | Pinned local LM inventory: per-domain JSONL, SHA-256/size, doc ids, canonical UTF-8 byte total, tokenizer fingerprint, split/subset, quick nested in full. Per-domain sufficient statistics; primary `equal_domain_text_ce_nats_per_token`; micro CE/BPB; `eos_inclusive_ce_nats_per_token_diagnostic`. Frozen `LMScoringPolicy` (context, stride in [1, ctx-1], fp32/bf16_autocast forward, fp32/fp64 log-probs, BOS/EOS/padding/position rules). `score_checkpoint_validation` scores a checkpoint in a separate process and binds the weights SHA-256 and state digest actually loaded. |
| `evaluation/search_tier.py`, `suites.assert_blimp_tier_membership` | Declared inputs pinned by `manifest_id`; tier must match; `isolated_final` refused; no final authorization is ever built; new BLiMP whole-subdataset partition check over a declared universe. COMPLETE only with complete declared coverage, else PARTIAL; zero-scored tasks report `None`. Endpoint confirmation = confirmation LM (disjoint from development inventories) plus optional confirmation-tier benchmark. |
| `training/evaluation.py` | Controller. `record_crossings` runs right after commit and **before** the periodic checkpoint; `run_pending` scores after the update returns, and first thing at the restored boundary on resume. Scoring uses a deep-copy replica whose digest must equal the crossing digest. `TrainingStateGuard` restores RNG (Python/NumPy/torch CPU/CUDA), per-module modes and grad mode, and verifies params, all buffers, module scalar attributes, grads, optimizer, schedule, objective, scaler, counters, committed cursor, science receipts and runtime flags. A live change fails the attempt and leaves the trainer requiring recovery. |
| Integration | `Trainer(evaluation=...)` (refused for legacy); strict-data `evaluation.science` config, validated only when present; controller built in `construct_training_components` before the training reseed and passed at CLI train, CLI resume and queue; resume at budget drains owed events; a changed plan or evaluator refuses ordinary resume; `score_document` gains the additive `scored_text_targets` diagnostic. |

Evaluation scores a replica because rolling windows rebuild RoPE caches (audit
row 11); harness reseeding (row 6) is undone by the guard. It runs synchronously
between updates: no concurrent GPU train/eval, no speculative state, no split update.

## 3. Results (authored/synthetic fixtures only)

- **First crossing:** 15 natural 65,536-target updates reach C=983,040 with no 1M event. The 16th commits C=1,048,576 and fires `quick_lm@1000000` there (receipt: `planned_threshold=1000000`, `actual_committed_targets=1048576`); all 16 LR receipts have N=65,536.
- **Multiple crossing:** one update C 0→16 makes `quick@8, search@12, quick@16, full@16` due in that order. `quick@16` shares `quick@8`'s computation (`shared_computation_with`) with its own receipt; full reuses quick documents' scores.
- **Endpoint:** budget 40, batch 16 → updates 16/16/8; endpoint fires once at C=40; resuming the final checkpoint scores nothing. Zero-valid work fires nothing.
- **Trajectory:** stochastic (dropout) runs with and without evaluation at non-aligned thresholds give identical LR receipts, weights (bitwise), optimizer state, cursor and CPU RNG. On CUDA (strict mode, bf16-autocast LM scorer, evaluator consuming CUDA RNG): weights, CPU+CUDA RNG and LR receipts identical.
- **Guard:** 10 live mutations (param, RoPE buffer, RoPE attribute, grad, optimizer, schedule, counters, cursor, science receipts, thread count) each fail the attempt and block checkpoint and further updates; a replica mutation fails only the score. torch 2.14 refusing to report matmul precision after mixed APIs is recorded as a change instead of crashing the guard.
- **Metrics:** hand-computed successor-oracle NLL with a code-point tokenizer (tokens ≠ bytes): text CE, EOS diagnostic, perplexity, BPB for ASCII/é/€/😀/mixed; NFD normalized before counting bytes; pooled ≠ mean-of-means; equal domain weights ≠ size weights; missing/extra/empty domains refused; rolling windows score each target once.
- **Resume:** a due-but-unscored event survives a crash and is scored first at the recorded digest; a completed but uncheckpointed attempt is adopted without rescoring; interrupted → failed → complete attempts are all preserved (canonical = attempt 3); retries stop at 3; a deliberate rerun keeps attempt 1 canonical; a different model state at the same event/step is never a cache hit.
- **Firewall:** search resolves only pinned local development inputs; final tier/manifest/split and `isolated_final` refused; BLiMP subdatasets from another tier's partition refused; tampered or missing files refused; truncated coverage → PARTIAL with `None` values; a real harness run over the authored fixture → COMPLETE.
- **Mutation check** (scratch copies of `src/`): 12 injected defects (no RNG restore on CPU and CUDA, score live model, crossing after checkpoint, latest-complete canonical, size-weighted primary, BPB per token, EOS in text CE, no reconcile, lineage ignoring identity, no BLiMP firewall, optimizer unguarded), all killed.

## 6. Risks and open questions

1. Scorer throughput on real inventories is unknown (per-target `.item()`).
2. Replica scoring doubles model memory during evaluation (fine at 50M; plan for 300M).
3. An event whose boundary state is gone (evaluation failed, training continued) stays FAILED. Re-scoring from an exact milestone checkpoint through `score_checkpoint_validation` is not yet wired into the ledger (M3).
4. The BLiMP universe must be supplied as data; the official subdataset list is not pinned in the repository.
5. HellaSwag/PIQA group halves are unchecked in declared manifests.

**Verdict: SAFE TO INTEGRATE as an opt-in within the authored/synthetic scope,
conditional on running the NOT RUN regressions (notably
`test_p35_science_workflow.py` and the two harness files) before merge.**
