## 1. Root causes

**A — order-dependent comparison (`cli/compare_cmd.py`).** Headline analysis,
eligibility, run identity, and seed summaries all read `*_evidence[0]` — the
first file in CLI argument order — while recorded-seed pairing was used only
for the spread summary. Reordered `--baseline`/`--candidate` files flipped a
divergent two-seed headline `+33.33` to `-33.33` and swapped run/seeds identity
(before-evidence `P23-D08/before`, exit 0 = reproduction assertions held).
Chance references additionally took the first hit across all files, silently
depending on order on conflict.

**B — lost draw multiplicity (`comparison/bootstrap.py::suite_bootstrap`).**
`arm_accuracies`/`task_differences` collapsed BLiMP draws into
`dict[cluster_id]` (macro over *distinct* clusters). Draw `[A, A, C]` with
cluster means 0, 0, 1 scored 1/2 instead of 1/3. Before-evidence: actual BLiMP
CI `(0.0, 0.5)` equals the independently recomputed collapse model and differs
from the occurrence model `(0.0, 0.667)` at `ci_level=0.8` (0.95 coincides at
the extremes by construction, so the 0.8 fixture is kept; production defaults
`n_bootstrap=1000`/`ci_level=0.95` unchanged).

## 2. Corrections

- **Pair-first flow.** Recorded seeds are paired (and duplicates, missing
  partners, and absent records refused) before any eligibility check, primary
  selection, or headline. A lone baseline/candidate file each without recorded
  seeds keeps the legacy single-pair path — no order dependence is possible
  with one pair, and the existing seedless public workflow
  (`test_offline_workflow_from_clean_environment`) keeps passing.
- **Primary-pair policy `numeric_lexicographic_min_v1`.** Headline uses the
  numerically smallest `(init_seed, data_seed)` pair (numeric, not string —
  tested with seeds 2 vs 10). Recorded as `primary_seed_pair` with the policy
  id; per-seed entries are seed-identified (`init_X_data_Y`); the full sorted
  pair set with evidence identities is bound into the payload (`seed_pairs`).
  The primary interval is labelled as within-run uncertainty for that pair,
  never cross-seed uncertainty. Pooled analysis is documented as a different
  analysis requiring its own policy, not as inherently invalid.
- **All-pair validation.** Every required pair must be eligible (annotated
  refusal otherwise); all pairs must cover identical item populations;
  duplicate input records within one evidence file are refused; chance
  references must agree per task across both arms and all pairs (conflicts
  refused, never first-file/averaged/defaulted). Metric definitions, suite
  weighting, and eligibility rules unchanged.
- **Occurrence-weighted BLiMP macro** in both suite helpers: replicate value is
  the mean over drawn occurrences of cluster means (whole-cluster resampling
  preserved, baseline/candidate draws shared). Full-data points are unchanged
  (each cluster occurs once). `cluster_bootstrap_difference` was already
  correct and is untouched (positive control).
- **Operational versioning.** `BOOTSTRAP_VERSION` 1→2, consumed (not
  decorative): `SuiteBootstrapResult.to_dict()` carries version, primary pair,
  and policy; `promote_command` refuses saved outputs lacking the current
  version/policy instead of satisfying promotion from stale statistics.
  Historical artifacts are untouched (D01-safe); inspection remains possible.
