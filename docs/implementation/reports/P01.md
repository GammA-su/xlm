## 2. Implemented Architecture & Contracts

### 2.1 Domain Contracts (`src/xlm/core/contracts.py`)
- **`CanonicalDocument`**: Normalized document model with strict metadata validation, source attribution, split validation, and immutable text payload.
- **`TokenShardManifest`**: Shard representation storing token counts, byte sizes, checksums, vocab sizes, and serialization schemas.
- **`InferenceInput`**: Input representation for evaluation and generation containing solely input tokens and attention/segment metadata. Crucially, strictly excludes labels and loss masks to prevent evaluation leakage.
- **`TrainingBatch`**: Training input representation with targets and loss masks, with explicit `.to_inference_view()` contract returning an `InferenceInput` stripped of target labels and masks.
- **`LMOutput`**: Forward model output containing logits and optional hidden states/attentions. Strictly excludes loss computation to ensure models cannot bundle objective losses internally.
- **`LossResult`**: Normalized loss output supporting `token_additive` and `custom_batch` aggregation modes, explicitly declaring token denominators and valid loss values (finite float check).
- **`ModelCapabilities`**: Capability flags declaring architectural limits (e.g. max sequence length, kv-cache support, vocabulary size).
- **`RunStatus` & State Machine**: State transition engine enforcing legal transitions:
  `DRAFT -> PLANNED -> ACQUIRING -> TOKENIZING -> TRAINING -> EVALUATING -> SUCCEEDED / FAILED / CANCELLED`.
- **`EvaluationReceipt`**: Complete C11 evaluation identity containing candidate model ID, benchmark ID, harness version, seed, task metrics, and reproducible signatures.
- **`ComparisonContract`**: Rigorous fair-comparison policy declaring baseline vs candidate constraints.

### 2.2 Component Registries (`src/xlm/core/registry.py`)
- Generic `Registry[T]` owning schemas, capability queries, serializer versions, and lazy factory loading.
- Pre-configured registries for:
  - `architecture` (Transformer, Mamba, Recurrent, etc.)
  - `objective` (CrossEntropy, etc.)
  - `optimizer` (AdamW, SGD, etc.)
  - `tokenizer` (SentencePiece, BPE, TikToken, etc.)
  - `source_adapter`
  - `transform`
  - `schedule`
- Zero PyTorch import overhead: validation and inspection execute in clean base environment without torch.
- Configuration-only fixture plugins demonstrated in test suite without modifying composer core.

### 2.3 Strict Configuration System (`src/xlm/config/`)
- Strict Pydantic v2 validation models (`extra="forbid"`, non-finite float rejection).
- Clear separation between `ExperimentDraftConfig` (may reference recipes/presets) and `ExecutableExperimentPlanConfig` (fully materialized, sealed, hashable).
- `UniqueSafeLoader`: Custom YAML loader detecting and raising explicit `ValueError` on duplicate keys.
- Composition Engine (`src/xlm/config/composer.py`):
  - Recursive `extends` inheritance with depth limits and cycle detection.
  - Preset resolution (`recipes/models/`, `recipes/mixtures/`).
  - List replacement semantics (subclasses overwrite base lists).
  - Conflicting component-type replacement (changing architecture or optimizer clears incompatible parent fields).
  - Deep mapping merge for shared dictionary structures.
  - Safe environment variable interpolation restricted to allowlist (`XLM_HOME`, `XLM_ARTIFACT_ROOT`, `XLM_DATA_ROOT`, `XLM_CACHE_ROOT`).
  - Dot-notation CLI overrides (`--override optimizer.lr=0.0003`).
  - Deterministic canonicalization and SHA-256 plan hash computation (`compute_plan_hash`).

### 2.4 Immutable Artifact Store (`src/xlm/artifacts/`)
- `ArtifactStore` located at configurable artifact root.
- Private atomic staging in `.staging/` before publication.
- Cross-process concurrency safety via `filelock` with locks maintained outside the publication target directory (`.locks/<id>.lock`), avoiding Windows file locking collision during directory rename.
- Atomic publication via directory rename.
- Idempotent re-publication check (matching checksums succeed; conflicting payloads fail with explicit `ArtifactConflictError`).
- Checksum verification on all files and directory manifests using SHA-256.
- Strict rejection of path traversal (`..` and leading `/` rejected).

### 2.5 Run Ledger (`src/xlm/artifacts/ledger.py`)
- SQLite-backed state ledger with Write-Ahead Logging (WAL mode), busy timeout, and foreign key enforcement.
- Durable recording of runs, artifact lineage, evaluation receipts, and comparison contracts.
- Plan-hash authorization binding: runs must match the authorized plan hash.
- Durable filesystem rebuild: `rebuild_from_filesystem` scans disk manifests and run records to reconstruct ledger state after cold restart or ledger loss.

### 2.6 CLI Tooling (`src/xlm/cli/`)
- `xlm config validate <path>`: Validate experiment draft or executable configuration.
- `xlm config resolve <path>`: Resolve presets, inheritance, and env variables into canonical executable plan.
- `xlm config diff <path1> <path2>`: Show structural differences between configurations.
- `xlm config schema <component_type>`: Dump registered component configuration schemas as JSON Schema.
- `xlm artifact inspect <artifact_id>`: View artifact manifest, files, checksums, and lineage.
- `xlm artifact verify <artifact_id>`: Validate integrity of all stored files against manifest SHA-256.
- `xlm artifact rebuild-ledger`: Rebuild the SQLite ledger from filesystem artifacts.
