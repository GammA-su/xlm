## Identity, bounds and compatibility

- Acquisition schema v2 binds selected files/ranges, revision, expected hashes,
  sampling declarations, limits and output identity. Existing plan files cannot
  be replaced by a different request. Legacy v1 plans/journals remain inspectable
  but cannot execute/resume with invented historical counters; a newly reviewed
  v2 job is required. Existing D01 schema-v1 artifacts retain checksum-only status.
- Transfer consumption is response-body bytes returned to the application,
  including measured metadata, redirect and retry/error bodies. Requests count
  each attempted open/follow. A failed read's unresolved reservation remains
  unavailable; there is no claim of exact unknown consumption, TCP/TLS wire bytes,
  provider cost or physical network traffic.
- Disk occupancy counts retained partial/raw files, published artifact copies,
  managed logs, nested scratch and journal/control bounds. Reservations are
  separate from occupancy and cumulative consumption. Scanning an owned inactive
  tree may release its ordinary disk reservations; transfer reservations are never
  released by a disk scan. Publication/external reservations require verified
  completion; an uncertain crash keeps them unavailable. No automatic unsafe
  reclaim operation was added.
- Selected JSONL scans a bounded prefix and charged lookahead. Parquet uses exact
  HTTP ranges and bounded metadata/row-group declarations, with stable strong ETag
  checks. All decoded selected row groups consume decompression allowance. The
  selected artifact contains exact row/byte or row-group locators and selection
  identity. Its row hash does not authenticate an untransferred whole original.
  Unsupported formats, ignored ranges, changed validators and oversized parser
  work are explicit refusals.
- D01 still stages/hashes requested bytes and rejects immutable conflicts. D02
  publisher identities declare actual module/dependency digests; this does not
  expand D06's authentic frozen-worker provenance claims. No trainer, evaluator,
  queue, artifact store or accounting service was duplicated.
- Prepare cumulative bounds include retries, `--force` and check-only children.
  Managed copy and log writes reserve first; stdout/stderr drain concurrently into
  owned bounded spools. Child disk occupancy is sampled (20 ms polling target)
  and checked before successful completion; this is **not an OS disk quota** and
  can observe a transient overshoot. Parser bounds and sampled RSS are **not a
  hard OS memory ceiling**. Python/Arrow allocations can exceed serialized-byte
  size; large real preparation still needs operator resource validation.
- Prepare record counts describe repeated inspection/processing work across
  stages, not unique corpus documents. Changed config, external watched/copy input,
  source code or lock cannot silently reset an existing account. Reuse of existing
  unchanged outputs remains supported. Private interrupted selected stages remain
  charged; new selection attempts replay deterministically without pretending the
  old request's bytes were free.
