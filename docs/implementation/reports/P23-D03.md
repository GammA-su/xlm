## Behavior, compatibility and limits

The public workflow prepares two distinguishable authored sources through the
registered `prepare` and `data tokenize` commands, compiles an exposure plan,
trains directly, plans/submits/runs the queue, and resumes an intermediate
checkpoint in a new process/home. Every path uses the same construction seam and
existing Trainer. Source/target traces verify actual inputs; the declared 75/25
mix and 33-target nonmultiple budget are checked against the real token shards.
The baseline also runs the public synthetic diagnostic evaluator with separate
training/evaluator provenance. These are partial authored diagnostics, not
official benchmark results or benchmark-selection evidence.

On the final authored workflow, both variants consumed **25 alpha targets and
8 zeta targets**, with zero repetition and matching actual target trace digests.
The trainable auxiliary moved from **1.0 to 1.029984474182129**. The public tests
require exact final computational-state equality for direct, queued and resumed
execution; these are observations from tiny authored runs, not benchmark metrics.

The nondefault test architecture scales actual forward logits, the optimizer
uses its registered nondefault epsilon, the fitted tokenizer is loaded through
its selected factory, and the auxiliary objective has a real trainable parameter
with nonzero updates. Factory/forward markers and captured module origins prove
invocation. The fixture objective additionally consumes Python, NumPy and Torch
RNG so continuation tests exercise restored RNG, not merely identical seeds.
These authored test mechanisms make no novelty or research-quality claim.

The stream preserves real source/document/lineage/token positions. It records a
hash chain over actual consumed targets and at most 256 detailed records per
step, with an explicit truncation flag. Isolation passes a real segment attention
mask into the model. Capped continuation keeps genuine document positions; only
true document boundaries reset them. A cap produces shorter padded windows with
one context token carried to the next visit. It does not preserve a full earlier
window as hidden context and does not insert EOS at cap boundaries.

New token exposure plans use version 2 identity to fix independently rounded
source quotas that could otherwise lose/add targets. Source quotas sum exactly
to the budget; runtime also enforces block-size visit limits. A compact block
preview is not a literal packed-document trace because context/document caps
can shorten visits. Historical plans/artifacts remain unchanged; recomputation
creates a new identity. Mixture state is explicitly versioned 2, with an exposure
identity guard; historical states require their original captured implementation.
Missing historical byte/RNG/execution evidence is never fabricated.

The new `experiment plan --smoke` exposes the existing queue's C13 tier, with
actual model shape inspection on meta: fewer than 5M unique deployed parameters,
at most 200,000 targets/600 training seconds/one GPU process/2 GiB new artifacts.
Disk is a hard reservation, not an invented measured estimate. Production planning
still requires its artifacts/profile/policy and plan-bound authority. The existing
public production CLI does not supply measured `profile_lookup`, so full-size
campaign planning is not claimed ready. Larger models were inspected on meta
only and refused by smoke validation. The handoff is specifically the bounded
baseline pilot described in [D03_BASELINE_PILOT.md](../D03_BASELINE_PILOT.md).

Selected inputs are bounded to 64 sources and 2 GiB aggregate shard bytes,
8 MiB/index entry, and 1,048,576 packed positions per optimizer update. Existing
tokenizer/plugin asset bounds and frozen-worker limits remain. Source exhaustion,
incompatible tokenizer/vocabulary, changed exposure/seed/policy, unused/missing
bindings and unsupported combinations fail explicitly.
