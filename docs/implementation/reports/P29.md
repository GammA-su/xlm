## Implemented changes and exactness

**Cleaning:** ASCII classification uses immutable deletion sets derived from Python's
own character predicates and `bytes.translate` to count in C. ASCII whitespace
includes U+001C–U+001F. Unicode retains the original loop. Integer counts, ratios,
filter ordering, reasons and thresholds are unchanged. Tests check the entire
Unicode domain and compare full cleaning outputs/metrics against independent counts.
Existing Markdown, placeholder email, real email, placeholder-plus-SSN and secret
preview regression tests passed.

**Tokenization:** each tokenizer holds at most 8,192 spelling→byte-length entries.
Lengths remain valid across vocabulary-ID changes. Protected BPE uses encoding token
spellings; externally supplied added-token backends retain vocabulary lookup because
`lstrip/rstrip` can alter encoding spellings. A targeted regression exercises a warmed
cache followed by backend mutation. `encode()` no longer builds byte spans that its
caller discards. Existing public batch behavior remains the scalar reference.

**Token storage:** validate and pack at most 4,096 IDs per binary write/hash update.
No NumPy dependency, dtype change, host-endian assumption, schema change or additional
intermediate token file. Tests cover empty, 1, 4,095/4,096/4,097/8,193 tokens, uint16
and uint32 extremes, invalid IDs, framing and exact scalar-reference binary bytes.
The paired writer benchmark compared every output file's SHA-256, including JSONL
offsets and both manifests/counters. Existing failure semantics remain; standalone
token writer durability is an existing limitation, not claimed repaired.

**Splitting:** accumulate byte counts while passing each document once to unchanged
group construction. Text and metadata are released instead of being retained by a
whole-corpus list. Sorting, diagnostic-first/audit-second/train-remainder, lineage,
quick subset and membership digests are unchanged. A weak-reference test detects
retaining prior documents; all existing split/freeze regressions passed. Metadata
still grows with document count: this is not an external-memory grouping engine.

## Cross-stage waste and intentionally unchanged areas

- Canonical JSON persists auditable stage boundaries; repeated parse/serialize is
  measurable but not the leading cost. No ad hoc sidecar, weakened schema, hidden
  verification cache or producer/consumer policy coupling was added.
- Token byte lengths are the useful compute-once value: bounded per-tokenizer cache,
  no disk sidecar, no artifact identity migration. Binary hashing now consumes the
  same bytes in blocks. Canonical `clean_hash` already exists; no duplicate cache.
- P25/P26 range projection/coalescing, pooled transport, redirect cache, streaming
  gzip and journal batching remain intact. Simulated latency dominates CPU decode
  in delayed regimes. Full fetch/resume scheduling was inspected but not newly
  benchmarked against actual HTTP; no speculative prefetch or concurrency rewrite.
- Repetition five-grams and PII regexes remain exact. No rolling-hash replacement,
  threshold change or optional-language fallback was introduced.
- Pool building and fit sampling still retain document objects. Tokenizer training
  still collects the bounded text sample. These are future memory projects; this
  milestone does not claim an unbounded-production pool/fit pipeline.
- Loader mmap/open reuse is a real architectural candidate (`MixtureBatcher._tokens`
  calls `read_tokens_mmap`, which opens a map per read); this run's loader is only a
  fixed prefix and cannot rank its cumulative production cost. No new pinned-memory,
  persistent worker, asynchronous H2D or cursor-lifetime behavior was introduced.
- Model supports explicit BF16/autocast, SDPA, compile and activation checkpointing.
  Trainer has `.item()`/finite checks; native evaluator has per-token `.item()`;
  harness scoring loops requests even though a native batched method exists.
  Fusing/reordering reductions could affect scores/numerics. GPU profiling is absent,
  so no fused optimizer, precision, model, loss or checkpoint scheduling change.
- No asynchronous checkpoint snapshot: copying optimizer state safely and preserving
  durability requires a separate measured design. Toy save timing is not a large
  optimizer checkpoint estimate. **Existing durability gap:** the observed save had
  zero `os.fsync` calls; `ArtifactStore.publish` writes/closes payloads and a completion
  marker then renames, without explicit fsync. Atomic visibility/checksum verification
  is not proof of power-loss durability. P29 leaves that behavior unchanged and does
  not certify durable completion. A separate durability repair must precede any
  asynchronous checkpoint optimization or production checkpoint acceptance.
- Official BLiMP/ARC-Easy/HellaSwag/PIQA data were never opened or scored. No score
  cache, task-policy change, label leakage, prompt retuning or sealed-data access.
- Local queue/orchestration unchanged. Adding cross-stage overlap without proving
  buffer ownership, resource accounting and deterministic recovery was not warranted.

## Production interpretation and next project

The remaining measured local leaders are tokenization/shards (~41% of optimized
100k time) and cleaning (~38%). Global production leadership is unknown: GPU
training, real transfers, P28 dedup, production BPE fitting and official evaluation
have no measurements here. No full-Mix-01 percentage can honestly be reported.

Conditional estimate only: at this exact distribution/512-vocabulary fixture,
53.16 s saved per 100k corresponds arithmetically to ~8.86 minutes per million
documents. It is not a production forecast. If analogous local preparation were
fraction `p` of a production run, observed savings imply total time reduction
`0.232 × p` (2.3% if p=0.1, 9.3% if p=0.4); `p` is unmeasured, not assumed.

Next highest-value project: measure production-sized vocabulary tokenization and
offset-index serialization on separately authorized representative local shards,
then test bounded shard-level tokenization/native batch concurrency against exact
byte-span/hash oracles. For total research campaign wall time, first obtain a
separately authorized GPU loader/compute/evaluation profile; do not extrapolate this
CPU audit into training claims. Pool/fit external-memory metadata remains the main
unresolved memory-scaling project after split retention was removed.

P28 handoff: no measured dedup optimization was discovered because dedup was
deliberately not executed. `dedup/minhash.py::MinHasher.signature` and
`dedup/engine.py` remain P28's profiling responsibility; expected gains are unknown.
Preserve `DedupResult`, split-group membership and lineage interfaces when integrating.
This branch contributes shared fixture/measurement tooling and a dedup-free timing
denominator, not an invented dedup cost or recommendation to change thresholds.
