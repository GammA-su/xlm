## 3. Implemented Architecture

### 3.1 Sealed-mode readiness (`operator/sealed.py`)

Readiness requires a configured sealed root outside all agent mounts, not
writable by the caller, plus an operator attestation naming
`separate-account`/`separate-machine`. Same-user directories, nested paths,
missing or bare-flag attestations all fail with named checks. Public
availability and pretrained-agent familiarity stay documented limitations.

### 3.2 Protected finals (`operator/final.py`, `xlm final`)

Frozen bounded requests (positive item/request caps, named variants, expiry,
nonce). Execution demands operator credentials, a ready sealed root, a
non-revoked authorization matching the exact request hash, a reviewed scorer
bundle (hash allowlist — arbitrary candidate code is refused even inside),
quota headroom and unexpired requests. Receipts carry aggregates only, enforced
both by schema (no per-item fields exist) and by boundary checks; replays,
alterations, unknown IDs, quota breaches and unbounded suppliers are refused.
Access log is append-only and hash-chained. Decontamination receipts record
counts, never matched text.

### 3.3 Release auditing (`operator/release.py`, `xlm release audit`)

Eleven checks: export integrity, code/lock/config hashes, admission records,
lineage, rights/provenance (unknown → BLOCKED, never certified),
reproducibility instructions, exposure labels, parameter/compute disclosure,
attribution, secret scan, final-label scan. Verdict RELEASE/HOLD/BLOCKED.

### 3.4 No-final-examples verification (same module)

`verify_no_final_examples` scans HF caches for materialized official final
splits (ARC-Easy test, HellaSwag/PIQA validation) and fails with file lists.
Purging requires an explicit operator confirmation flag.

## 4. Real Finding and Remediation (P15 smoke)

Running the new check against this machine's caches **failed honestly**: the
P15 ARC-Easy smoke (train-only, limit 10) caused `datasets` to fetch and
materialize the full config, including `ai2_arc-test.arrow` (660,168 B) and
`test-00000-of-00001.parquet` (346,257 B) at 2026-09-19 15:53 — during that
session. Project code never requested or read the test split (train-only
requests, suite firewall), but bytes were fetched into the shared cache.

Remediated with the implemented purge (explicit confirmation): both test files
removed, train/validation artifacts untouched, re-verification clean
(`clean=True`, 0 findings). Lesson recorded: official-data smokes must use
split-scoped loading; future runs will assert this before downloading.

## 8. Honest Scope Statements

- **No protected deployment exists here.** Two-identity separation is NOT RUN;
  the sealed checks prove refusal logic, not an established enclave.
- **Sandbox limits are documented, not proven.** No-network/read-only/bounded
  execution is enforced at the interface level; a subprocess is not a security
  boundary and the code says so.
- **Cache absence is not a non-read proof.** The check finds fetched artifacts;
  it cannot prove bytes were never read elsewhere.
- **No keys or final data in the repository.** Credentials live outside the
  tree by design; tests use synthetic fixtures only.
