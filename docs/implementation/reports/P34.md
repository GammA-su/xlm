## Optimizer authority (items 3–6, 18)

**Starting candidate had blockers.** A real CUDA step followed by an authored
completion-barrier exception was correctly rejected for prefetch, but silently
advanced on the synchronous loader. Both paths launch the same asynchronous
AdamW work: zeroing gradients and updating Python scheduler/counter values do
not establish CUDA completion. The barrier is therefore a Trainer requirement.
It now runs for every CUDA loader on the trainer's current stream. This covers
the frozen optimizer; arbitrary optimizers launching unjoined private streams
are not a newly certified extension.

Actual ordering, retained except for the barrier's scope:

1. Fetch exact budget-capped microbatches; calculate actual loss-mask target sum.
2. Forward/backward, finite checks, scaler unscale if applicable, gradient clipping.
3. Set `_update_in_doubt = True` immediately before optimizer/scaler step.
4. Optimizer step; scaler update when used; optimizer zero-grad.
5. CUDA current-stream completion barrier.
6. Apply next schedule LR; promote committed counter, processed counter, step.
7. `batcher.commit()` promotes the consumed update's end state locally.
8. Only after commit returns, clear in-doubt; reset skip count, form metrics,
   and optionally publish a checkpoint.

| Injected boundary | Trainer counters | Data cursor | In doubt / consequence |
|---|---|---|---|
| Before H2D / during accumulation | Old | Old | No optimizer mutation; tested CPU retry is exact |
| Optimizer or CUDA completion | Old | Old | Yes; no retry/save; fresh durable reload |
| Scheduler advancement | Old (LR may partly change) | Old | Yes |
| Processed-counter addition | Committed counter already promoted | Old | Yes |
| Before cursor promotion | All counters promoted | Old | Yes |
| Cursor promoted, commit function raises before returning | All promoted | New | Yes; conservative durable recovery |
| Checkpoint publication after successful commit return | All promoted | New | No; optimizer/data boundary is authoritative even if publication fails |

The candidate's vague `after_commit` test injects **inside** the commit call,
after cursor mutation but before successful return. It is not a test of a
failure after the full optimizer/data boundary. The added publication-failure
test distinguishes the latter explicitly.

No Trainer load/reset API clears the flag. Batcher `load_state`, rollback,
restart/close do not reset Trainer authority. `train_step`, `train` (including
already-completed/stop-requested calls), autosave and finalization all refuse
while in doubt. The public checkpoint manager attached to the Trainer formerly
bypassed `_save_checkpoint` and published mismatched state; a bound authority
guard now refuses that path before staging. A freshly constructed independent
domain checkpoint manager still requires its caller to supply coherent objects;
this is not protection against arbitrary Python code replacing private state.
Rollback failure preserves the original training exception.

Checkpoints still serialize only `get_state()` (committed data), use the existing
atomic durability protocol, and discard/recreate speculative work on reload.
Positive checkpointing with a future update already in flight and exact resumed
training pass existing producer-training tests and the public CUDA workflow.

## Pipe/lifecycle findings and repair (items 7–9, 16–17)

The residual send race was **not bounded** by the candidate's response timeout:
`send`, a partial `recv` after `poll`, the divert reader's join, and shutdown's
draining receive could all block outside it. A suspended real Windows child and
a 2-MiB control frame demonstrate the send defect: a configured 100-ms deadline
was ignored until an independent test watchdog killed the child at 3.016 s.
This proves a blocking-write hole without claiming deterministic reproduction
of the precise microsecond-sized tiny-write interleaving.

The repair generalizes the reset divert reader into one lifetime inbound reader,
with a bounded bytes inbox (`depth + 2` entries). All control sends have a
deadline; the consumer receives completed frames from the inbox, so a partial
kernel read cannot trap the trainer. Reset acknowledgments are consumed before
another reset can accumulate them. A protocol wait also has a deadline. No
event loop, new producer, shared tensor storage, or speculative authority was
introduced. Production remains one spawned producer and depth one. Even if a
full inbox stalls draining, a control send times out and reaps the child.

Shutdown no longer drains the pipe synchronously. It stops the reader, closes
only after an overlapped read finishes, and otherwise terminates the owned child
to complete EOF before releasing handles. Join/terminate/kill waits are finite.
The first lifecycle probe exposed a Windows in-flight Overlapped destructor
warning in the initial repair; that result is preserved separately. The final
probe has no such warning. Close/GC, killed-child restart, back-to-back resets,
and hard consumer process exit pass. Already-consumed work can still commit
after producer death because commit does no IPC.

Parent send/poll/receive/closed-handle/EOF failures become `PrefetchProducerError`;
known remote source/exhaustion errors retain their documented domain types.
Failed sends discard unreturned pending ownership. Transport failures never
promote committed state. Frame-limit errors are rejected before unpickling.
The supported endpoint is an owned child executing captured code, not a hostile
pickle service: a frame limit is not a safe-unpickling guarantee.

Payload calculation: frozen context 512, maximum configured target batch 65,536,
all research recipes; input shard uint16/uint32 both become compact int64 arrays.
Five int64 training arrays = 40 bytes/position; bool attention = 1; three int32
provenance codes = 12; int64 byte-span pair plus offset = 24: **77 bytes/position**.
Padding/document boundaries mean 65,536 valid targets are NOT an upper bound on
positions. The existing packer cap is 1,048,576 positions, hence **77 MiB** of
arrays. Independently hashed metadata, string table and end state each have an
8-MiB limit: at most about **101 MiB plus bounded pickle overhead**. The new
**128-MiB frame admission cap**, on serialization and `recv_bytes(maxlength)`,
accommodates this domain and rejects an advertised oversized frame before
allocating its advertised body. This is why an arbitrary 16-MiB transplant was
not appropriate. A measured normal frame was **5,099,237 bytes / 66,048 positions**.

Depth/request accounting bounds logical speculation. The raw inbox has a separate
explicit bound; reader-local and peek frames add at most two frames beyond it.
This does not establish a 2-GiB process-RSS quota: Python packing objects, verified
input indexes and allocator overhead also consume memory. No unsupported RSS
guarantee is claimed. Idle child command waits are intentional; every parent
I/O wait is bounded (default 300 s, finite positive values only), with bounded
teardown added. A protocol wait can spend one final receive interval in addition
to its outer deadline; it is not an exact wall-clock 300-s SLA.

Final eight-iteration full-size CPU stress: construct, consume, rollback,
regenerate, commit, close; one killed-child/restart iteration and one GC-only
cleanup. **Zero children and transport threads after every iteration; 336 handles
each time; RSS 531.59–533.68 MB, ending below its first observation.** Evidence:
[review_cpu.json](../evidence/p34/review_cpu.json). This is bounded stress, not a
multi-hour campaign or proof of an OS-enforced process-memory ceiling.

## Trace and content semantics (items 10–13)

No trace product change was needed. The fast path uses `type(x) is int`, not
`isinstance(x, int)`: **bool never formats as 0/1 in the fast path** and retains
the reference's JSON true/false through fallback. Exact string types likewise
avoid subclass conversions. The same C ASCII escaper as `json.dumps`, sorted-key
layout, comma/colon separators and default `ensure_ascii=True` produce identical
bytes. Percent signs in template strings are doubled; the incoming previous
digest is escaped once, later digests are plain lowercase hex. `%d` matches
integer JSON spelling, including negatives, zero and arbitrarily large supported
Python integers. Python's own integer-string digit limit is unchanged.

New deterministic generation compares **every SHA input byte string**, not only
the final digest: 120 varied windows, negative/200-digit integers, bools in numeric
positions, empty strings, quotes, slash/backslash, percent, control/NUL/tab/newline,
non-ASCII, astral code points, lone high/low surrogates, U+2028/U+2029. Existing
tests cover malformed/fallback values, record byte limits, epoch wraps, the
256-record diagnostic truncation and byte-coverage flag. The per-record 8-MiB
limit and original reference remain authoritative.

Content hashing covers row partitions, light metadata, all training arrays
(IDs, labels, loss/attention masks, positions, segments), all attribution/doc/
lineage codes, byte spans, offsets and the string table, including shapes/dtypes.
`verify_content=True` recomputes this on the trainer's received storage; hashing
only in the child cannot detect corruption between encoding and consumption.
It complements, rather than duplicates, committed-state/start/end binding.

Four additional admission defects were reproduced and repaired: an empty `rows`
claim previously returned before content verification; payload generation and
ordinal were unchecked; after budget misprediction/regeneration the second
returned budget was not checked. Validation now precedes empty-return handling,
checks those envelope fields, and enforces the requested target ceiling. End-state
digest recomputation binds mixture/scheduler position, epochs, cursors, trace,
exposure identity and committed target delta. Nineteen independent tamper cases
reject before pending ownership/committed progress, including every array and
the envelope/end-state claims. The digest is integrity binding for the owned
producer, not authentication against a child deliberately forging all hashes.

Budget tests compare synchronous/prefetch tensors and committed state at exact
multiples, one target below/above and a single-target final update; rollback and
state reload immediately before the final partial regenerate identically. Existing
depth-two partial, mixture, epoch/replay and actual-50M wrap tests remain selected.
No target count exceeds the requested budget.
