## 3. Implemented Architecture

### 3.1 Collectors (`reports/collect.py`)

Run, campaign and dataset reports assemble exclusively from authoritative
stores. Absent figures are recorded as missing and rendered "n/a" — never
zero-filled. Protected keys (sealed text, labels, benchmark examples, secrets)
are stripped and secret-like values redacted at collection time, so no renderer
can leak them later. Exclusion inputs keep aggregate counts only.

### 3.2 Renderers (`reports/render.py`)

Canonical JSON, CSV metric tables, Markdown and fully self-contained HTML
(inline CSS/SVG, no external assets — pages stay readable after moving).
Data-originated text is escaped per format; an HTML-injection fixture renders
inert everywhere. Learning curves show raw points plus a labeled
trailing-average smoothing line in separate token views. Failures, partial
coverage, comparison violations and seed counts stay visible.

### 3.3 Dashboard (`dashboard/server.py`, `xlm dashboard`)

One stdlib Python UI reusing the report services. GET-only routes (405
otherwise), loopback binding by default, non-loopback refused without an
explicit authenticated deployment config, no telemetry. Serves run, campaign
and dataset pages built from the same collectors as the static exports.

### 3.4 CLI

`xlm report --run|--run-record|--campaign|--data-inputs` in four formats,
`xlm runs list` over queue/ledger states, `xlm dashboard` with bind controls.
