## 3. Implemented Architecture

### 3.1 Source families versus views (`src/xlm/data/pools/views.py`)

A **family** is an upstream corpus; a **view** is a deterministic, data-only selector
over fields the adapter actually recorded (source IDs, document kind, language, split,
metadata equality, byte window). The distinction exists for sampling weight: two views
that both select a document would expose it twice if both carry mixture weight.

`OverlapPolicy` makes the treatment explicit — `EXCLUSIVE_ASSIGNMENT` (highest
priority wins, ties on `view_id`, so total weight is conserved) or `MULTI_VIEW` (kept
in every view, with the repeated assignments counted and warned about). There is no
implicit third behaviour.

`audit_overlap` reports view count against **distinct family count**, so two views over
one family are reported as one source of text rather than two.

### 3.2 Frozen pool manifests (`manifest.py`, `builder.py`)

`PoolBinding` carries every input that determined contents. Six components are
required; `assert_publishable` refuses publication when any is missing or empty,
because an unbound pool cannot later be told apart from one built under different
rules. `build_pool_id` derives identity from `binding.identity()` plus the membership
digest, so a changed normalization rule, filter threshold, source revision or view
selector produces a different pool.

`verify_pool_offline` re-derives **two** digests from documents on disk: membership
(which documents, in which split) and content (by clean hash). The content digest is
what catches text edited under unchanged document IDs — membership alone cannot.

`PoolTier` is **derived from measured training bytes**, never asserted by the caller,
so a demo pool cannot be relabelled production by editing a field.

`detect_split_leaks` runs as a publication gate: a duplicate cluster or split group
straddling train and diagnostic validation, or a parent document in another split,
refuses the freeze.

`assess_sufficiency` reports distinct training bytes, an estimated unique-token count,
the required epoch count and the repeated-exposure token deficit. C07 forbids
unreported repeated exposure, so a shortfall is surfaced before a run is planned.

### 3.3 Tokenizer-fit sampling (`tokenizer_fit.py`)

Balanced by **declared raw-byte shares**, not document counts — a family of long
documents would otherwise dominate by record size. Selection order is a keyed hash of
the frozen seed, so the same pool reproduces the same sample regardless of input order.

The train-only guard runs **before** any selection, so a leak cannot half-happen.
`restrict_membership_to_split` is the ergonomic path for a multi-split pool; the guard
remains as a backstop for a caller that skips it.

`tokenizer_fit_resource_plan` returns a labelled estimate (peak memory, network not
required, whether authorization is needed) and authorizes nothing.

### 3.4 Research regime versus campaign freeze (`regime.py`)

`ResearchRegimeManifest` binds pool, tokenizer, diagnostic corpus, exclusion and split
policies, and reference training/evaluation settings. It deliberately does **not** name
a mixture — `binds_a_mixture` is `False` — so selecting a mixture during data search
cannot look like the regime was already settled. `CampaignFreeze` is the later object
that binds the winning mixture and exposure plan.

`DiagnosticCorpusFreeze` validates that the quick subset is genuinely nested and that
the membership digest matches its IDs, so the diagnostic set cannot be swapped out.

### 3.5 CLI

`xlm data pool build` / `inspect` / `verify`, and `xlm data freeze` (with
`--plan-only` / `--fit`).

## 7. Honest Scope Statements

- **The production 32,768 BPE fit was NOT RUN.** The capability is implemented and the
  resource plan is produced (`--vocab-size 32768 --plan-only` executed, exit 0), but
  the pilot pool holds 1,400 distinct training bytes. Fitting a 32,768 vocabulary on
  that would produce a meaningless artifact. The executed fit used vocab 512 and
  yielded 468 actual tokens, and the tokenizer correctly reports
  `is_production_baseline = False`. The real fit waits on admitted sources in P13.
- **`ESTIMATED_BYTES_PER_TOKEN = 4.0` is a planning constant, not a measurement.**
  Every sufficiency figure derived from it is labelled an estimate in the report, the
  manifest and the CLI. Exact token counts require the frozen tokenizer (P12).
- **The resource plan's peak-memory figure is an estimate**, stated as such in the
  plan's own `basis` field. It is not a benchmark of the `tokenizers` library.
- **`PRODUCTION_MIN_TRAIN_BYTES = 1 GiB` is a project policy threshold**, not an
  external standard.
- **Pilot data only.** Every document is authored synthetic fixture text flowing from
  P09 and P10. No live corpus was acquired and no remote tokenizer fit was attempted.
- **Overlap detection is structural, not semantic.** It finds documents selected by
  more than one view. It cannot detect that two families independently contain
  paraphrased versions of the same upstream text; that is the dedup path from P10,
  with its own stated false-positive and false-negative limits.
