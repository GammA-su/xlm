## 2. D02 closeout findings and corrections (committed on `fix/d02` as `15aaadb`)

**1A — remainder accounting.** Review confirmed the criticism: reads return up
to 8192 bytes while only one probe byte per pipe was recorded, so stale
over-read remainders (up to 8191 bytes) vanished without a category. Corrected
`prepare/bounds.py::drain`: reads are capped at the live remaining allowance
(hard read limit, no reservation held across blocking reads, so no idle-pipe
starvation/deadlock); retained bytes reserve/commit before spool writes; stale
remainders are counted by actual length as `discarded_child_overflow_bytes`
(cap `2 * max_attempts * 8192` — at most one chunk per pipe per attempt); the
1-byte lookahead (`discarded_child_probe_bytes`, unchanged cap) fires only at
zero allowance to separate overflow from EOF. Retained + both discarded
categories exhaustively cover every returned byte; bytes left in the OS pipe
buffer at kill time were never returned and are correctly uncounted. New tests:
`test_child_output_categorizes_every_returned_byte_under_tiny_allowance`
(16-byte cap, barrier-synchronized 8192-byte scripted pipes on both streams,
exact retained+discarded==recorded-returned equality plus journal reload) and
`test_child_output_tiny_allowance_over_real_pipes`. Stability: closeout1,
co06–co10 green (8/8 each); earlier co01/co03–co05 runs preserved a too-strict
exact-count assertion that was corrected to scheduling-independent invariants.

**1B — budget vs execution/output identity.** No rewrite was needed; evidence
added. Cumulative budget identity (`PrepareBounds`: config id, aggregate
budgets, watched/copy input *paths*, code, lock) is shared across stale reruns
with persistent spending. Execution identity
(`planner.hash_stage_inputs`: full stage spec incl. `max_bytes` and command,
variables, code/lock digests, watched/copy *content* digests) still marks
changed bytes/policy stale, never reusable; output identity
(`hash_stage_outputs` + verification) still requires re-verification;
per-stage limits are enforced in `_copy_bounded` and recorded per attempt;
completed originals stay immutable (atomic-complete refusal + D01 conflicts).
New test `test_stale_rerun_keeps_cumulative_account_without_reuse` proves stale
verdicts, enforced/recorded limits, cumulative counters, distinct attempt
records, and untouched prior outputs.
