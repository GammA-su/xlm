## 3. Implemented Architecture

### 3.1 Pinned harness adapter (`evaluation/harness_lm.py`, `evaluation/harness.py`)

- The harness version is pinned (`SUPPORTED_LM_EVAL_VERSION = "0.4.13"`);
  `require_harness()` refuses a different installed version rather than running
  unpinned.
- `XlmHarnessLM` registers through the public `@register_model("xlm")` registry —
  installed third-party code is never edited. `loglikelihood` /
  `loglikelihood_rolling` delegate to the native `ConditionalLikelihoodScorer`
  (empty context uses BOS; rolling uses the text-BPB convention with structural EOS
  excluded and named separately); `generate_until` uses the native generator with
  `until`/`max_gen_toks` handling.
- `HarnessIdentity` fingerprints checkpoint, tokenizer, variants, dataset
  revisions, splits, template, normalization, truncation, precision and limit.
  Suite runs set `use_cache=None` so the harness's own response cache can never
  override XLM identity checks.

### 3.2 Explicit tiered variants and split firewall (`evaluation/suites.py`)

- Official revisions pinned from `manifests/eval_dataset_pins.yaml` (metadata-only
  resolution, real SHAs recorded).
- Per-tier variants: ARC-Easy train/validation/test; HellaSwag and PIQA grouped
  train subdivisions for search/confirmation and official validation for final;
  BLiMP whole-subdataset partitions (≈20/20/60, deterministic, disjoint).
- `resolve_suite(FINAL)` raises `FinalAuthorizationRequiredError` without an
  operator authorization; `assert_no_final_split_leak` blocks developer variants
  that point at final splits. `build_final_request` freezes a hashable
  operator-only request (execution is P21's).
- `materialize_pinned_tasks` copies each official harness YAML verbatim into a
  private directory and adds only the immutable `dataset_kwargs.revision` and the
  wrapper task name — no reimplementation of prompts or preprocessing.

### 3.3 Four-task index (`evaluation/suites.py`)

`S = 100 × mean((acc − chance)/(1 − chance))` with BLiMP macro-averaged over whole
subdatasets before weighting ¼ each; chance 0.5 (BLiMP/PIQA), 0.25 (HellaSwag),
mean inverse choice count (ARC). Missing or zero-scored tasks withhold the index;
negative components are not clipped.

### 3.4 Evidence and references (`evaluation/evidence.py`, `evaluation/reference.py`)

Per-item likelihoods, choice scores, margins and identifiers are stored with the
full identity; truncation, omissions, errors and run limits are explicit.
`EvidenceCache` returns a cached result only on exact identity match.
Reference registrations measure parameters locally (no model-card copying);
`ModelDownloadPlan` refuses any download without an operator ticket, immutable
revision, byte cap, allowlisted hosts and a scratch dir.

### 3.5 CLI (`xlm evaluate`)

`--suite synthetic_mc|synthetic_pair|all` is unchanged. New
`--suite search|confirmation|final` runs the harness path with `--tasks`,
`--include-path`, `--limit`, `--output-dir`, `--pins`, `--request-only` and
`--final-authorization`. Final without authorization exits 1 with the firewall
message; `--request-only` writes the frozen request.

## 7. Honest Scope Statements

- **Full official search/confirmation suites were NOT RUN.** Only one bounded,
  clearly labeled live smoke (ARC-Easy train, 10 items, untrained tiny model) was
  executed; it is not a benchmark score and no suite index was produced.
- **Final is operator-blocked by design.** The request path is frozen and tested;
  execution belongs to P21's isolated operator environment.
- **No model downloads occurred.** Comparator registration is local; the download
  plan is a gate, not an executor.
- Harness parity evidence is exact on authored fixtures and the bounded live
  slice; it does not establish official leaderboard scores.
- BLiMP subdataset names are fetched from the pinned harness registry at run time;
  the partition is deterministic but "about 20/20/60" is a policy target, not a
  proven statistical balance.
