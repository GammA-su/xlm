## 2. Exact/MinHash architecture before changes

Two streaming passes: pass 1 normalized every match view twice (exact hash
+ shingle tokens), hashed shingles with BLAKE2b, ran a 128-permutation
Python min-loop (13.3 ms/doc, 96% of wall), and appended JSON lines to
partitioned exact/band indexes plus a JSON signature file. Pass 2a unioned
exact groups; pass 2b expanded LSH buckets into a Python set of string
tuples, reloaded needed signatures from JSON, verified estimated Jaccard,
and built clusters with a frozen content-based survivor rule; survivors
streamed through a second read with cluster annotations. The CLI defeated
the streaming design by materializing the corpus list twice. Config,
cluster, lineage, and report shapes are unchanged by P28.

## 3. Exact dedup optimization

- Match view computed once per document and shared between exact hashing
  and shingle tokenization (was: two full NFKC/casefold/regex passes;
  measured 0.67 s → 0.23 s on 2k docs).
- `clean_hash` is NOT reused, deliberately: exact identity is
  `sha256(match view)` so punctuation/case-only variants collide, while
  `clean_hash` covers canonical text. A committed test proves the
  divergence (pair collides exactly with distinct clean hashes); P27B's
  "free fingerprint" observation therefore does not apply to exact
  identity, documented here.
- Index partitions use versioned binary framing (magic + u16 lengths,
  1 MiB buffers) instead of JSON lines; groupings identical, foreign or
  truncated files fail closed (tested).
- Representative selection untouched (union-all + frozen survivor rule).

## 4. MinHash optimization

- Exact uint64 vectorized kernel for `min_h((a*h+b) % P)`, P = 2**61 − 1:
  `h = h1·2**61 + h0` plus 31-bit limb evaluation, every intermediate
  provably below 2**64 (bounds in code comments). 613-case fuzz proof
  (configs × sizes 0–1500 + 64-bit boundary hashes) plus a committed
  skip-gated equivalence test; 5× (11.9 → 2.3 ms/doc) where NumPy exists,
  exact Python fallback otherwise. Shingle definition, seeds,
  permutations, thresholds all frozen.
- Shared match view (above) removes the second tokenization.
- Pass-1 signature generation parallelizes by input shard (1/2/4/8
  benchmarked); workers stream docs, write deterministic facts-JSONL +
  fixed-width signature-binary shards, and never pickle documents.
  Worker count cannot change results (ordered parent consumption; proven
  across 1/2/4 workers × single/manifest layouts).

## 5. LSH/candidate optimization

- Candidate pairs packed as `uint64` ordinals (`a<<32|b`), sorted
  numerically: ~8 bytes vs ~100+ per string tuple, no doc-ID strings in
  RAM. Order differs textually from lexicographic doc-id order, but union
  connectivity, pair counts, and match-kind sets are order-independent —
  proven identical to the reference on every AC fixture.
- Oversized-bucket recording and per-document budget logic unchanged,
  now keyed by ordinal.
- Signatures load by ordinal seek (no full-file scan); only candidate
  documents are retained, as before.
- Verification batches integer equality in NumPy chunks (4096 pairs) with
  a pure-Python fallback; float division kept elementwise-identical to
  the scalar reference.

## 6. Cluster optimization

Kept the existing union-find: profiling shows clustering at 0.02 s on
2k docs (noise against minute-scale signature phases), so no compact
rewrite was warranted — measured, not assumed. Survivor rule, cluster
IDs (sorted-membership digests), and output sorting are byte-identical
across worker counts, unit layouts, partition counts, and shuffled
inputs (existing + new AC tests).

## 7. Sharded input/output behavior

Input: single `.jsonl` (newline-aligned ranges, exact blank-aware counts,
physical line offsets for identical errors), verified P27A clean
manifest (full `verify_manifest` before planning, one unit per shard),
plain directory (legacy fan-in), Parquet — never concatenated into one
temp file; logical results identical across layouts (tested). Output:
legacy `documents.jsonl` (atomic replace) or P27A `dataset-manifest.json`
+ target-sized shards via `ShardedJsonlWriter`; `dedup_report.json`
shape unchanged, plus `dedup_throughput.json`. Any worker failure or
planning error removes staging and publishes nothing.

## 10. Embedding artifact design (P28-M)

`embedding-manifest.json` v1: schema version, source artifact identity
(kind/counts/bytes, plus clean aggregate for manifest inputs), model
identity string, dim, dtype (float32/16), normalization flag,
truncation policy, ORDERED doc IDs, per-shard (path/rows/dim/dtype/
sha256), totals. Vectors in contiguous `.npy` shards (never JSON).
Validation fails closed on: version, dim/dtype mismatch, missing shard,
hash mismatch, row-count mismatch (stdlib `.npy` header parse — no NumPy
needed), ID count/duplicates, totals, and optional exact source match.

## 11. Backend architecture (P28-P)

`NeighborBackend` protocol (build/add-once, batched top-k search with
deterministic score-desc/ordinal-asc ties, self-exclusion): `python`
(pure exact, everywhere), `numpy` (exact chunked matmul + cutoff masking
so ties resolve identically to exhaustive search), `faiss-cpu`
(IndexFlatIP, rows re-sorted on CPU; tied sets truncated inside FAISS
documented as the one cross-backend divergence), `faiss-gpu`
(`StandardGpuResources` + `index_cpu_to_gpu`, fails loudly without
either). `auto` prefers faiss-gpu → faiss-cpu → numpy → python and
records the resolution; pins never silently downgrade. IVF/PQ left as a
clean extension point (protocol accepts index params; FlatIP first per
P28-Q/R).

## 16. Memory / VRAM scaling

Raw vector memory follows N × D × dtype bytes exactly (1465 MiB at
1M × 384 float32, measured). Design: memmap shard reads, one documented
concatenation copy for the NumPy backend, bounded query batches
(batch × N × 4 B; 4096 × 100k = 1.6 GB transient was measured at +1 MiB
parent RSS delta after release — batch memory is transient). Never an
N × N matrix (largest transient: one query batch × corpus). VRAM is
unmeasurable here (no FAISS): telemetry records null with the reason;
operator GPU runs fill it in.

## 17. Semantic candidate determinism

Byte-identical candidate files across reruns; identity hash covers clean
identity + embedding identity + backend family + index params + top_k +
threshold (+ policy) and excludes hardware timing. Tie cutoffs resolve
by ordinal on every exhaustive backend (numpy == python proven incl. a
6-way tie fixture); Python backend is the determinism oracle that runs
in every environment.

## 18. Confirmation semantic lane is OFF by default

`data dedup` accepts no semantic flags and its outputs are proven
identical before/after any semantic sidecar run (committed test). The
default and only unspecial product of the lane is `candidates.jsonl` +
report; the experimental threshold-union clustering requires an explicit
`--semantic-cluster-policy v0-experimental-threshold-union` and only adds
an analysis block. No survivor path reads semantic output.

## 19. Threshold-analysis tooling

`summarize_thresholds` (and the report block) give score min/max,
p50/p90/p99, and per-threshold (default 0.90/0.92/0.94/0.96/0.98)
candidate counts, component counts, and top component sizes — analysis
points with an explicit not-a-policy disclaimer; no threshold was
selected (that validation belongs to the 50M experiment).

## 20. Recommended next step for P29

Consume `clean_hash`-keyed exact groups and MinHash signatures as the
pool-freeze/split inputs (they are already deterministic and sharded);
do NOT rebuild fingerprinting downstream. For speed: attack parent
single-threaded phases next (index-add JSON parse, candidate grouping —
now visible at ~40% of kernel-accelerated wall), not the min loop.
For recall: IVF/PQ behind the backend protocol with recorded
(nlist/nprobe/PQ/seed) identity, evaluated against the FlatIP oracle on
the committed tie fixtures. For policy: keep semantic sidecar-only
until a 50M-scale threshold experiment exists.

## Open limitations

- Locked-env single-worker lexical speed is at parity with baseline
  (Python fallback); the wins are parallelism (5×) and the NumPy kernel
  (5×) where NumPy exists.
- 1M exact CPU search is hours-long: approximate indexes deferred to P29.
- Quarantine-style caps do not exist for candidate output; threshold
  selectivity bounds it (documented; adversarial identical-vector
  corpora would explode the sidecar, never survivors).
- `recorded_at`-style run-dependent fields: candidate scores are
  deterministic floats; backend `search_seconds`/RSS are telemetry only.
