## 3. Implemented Architecture

### 3.1 Backend policy (`models/backends.py`)

`resolve_attention_backend` resolves `eager`/`sdpa` with a recorded report and
**refuses** `profile_required` at execution time. SDPA kernel availability is
probed functionally (real ops under each `sdpa_kernel` context), not assumed:
this wheel reports `flash=no, mem_efficient=yes, math=yes` ("Torch was not
compiled with flash attention"), and the report says SDPA uses a slower kernel.
Arbitrary-mask fallback is reported, not hidden. `maybe_compile` is explicit
opt-in with a report; `compile_probe` honestly tests codegen availability.

### 3.2 Precision, checkpointing, compile (`training/trainer.py`, `models/transformer.py`)

Precision is validated loudly (`VALID_PRECISIONS`); BF16/FP16 on CPU raise
instead of silently running fp32. FP32 master weights are kept under autocast.
Activation checkpointing is an opt-in per-block recompute flag (refuses hidden-state
recording while active). Compiled execution keeps the uncompiled module for
checkpoints (no `_orig_mod.` prefix breakage). FP16 overflow follows the
loss-scaler protocol — bounded skip-and-backoff without consuming data, then loud
failure past the cap — instead of defeating loss scaling with an instant raise.
`execution_report()` records the exact modes of every run.

### 3.3 Scaler persistence & OOM recovery (`training/checkpoint.py`, `training/recovery.py`)

Checkpoints carry `scaler.pt` (FP16 only, never faked) and a `precision` field
(default `fp32`, backward compatible). Resume without a scaler is refused unless
explicitly forked. `plan_oom_recovery` restarts same-contract only with cursor
continuity; any precision/backend/microbatch/compile change forces a recorded fork.

### 3.4 Profiler (`training/profile.py`, `training/profile_worker.py`, `xlm profile`)

Bounded dry steps on synthetic tokens through the **real** stack (trainer,
optimizer, checkpoint). One isolated worker process per microbatch size with a
timeout, so OOM cannot poison the caller; workers calibrate under private
`XLM_HOME` roots so checkpoint IDs can never alias another model's artifacts.
Ascending search stops at the first infeasible size; the global batch is preserved
by integer accumulation; context/precision/architecture are never reshaped to fit
(preflight refuses instead). `plan_resources` quotes measured throughput/ETA
intervals, separates checkpoint-save overhead, counts exact parameters/optimizer
bytes, and estimates FLOPs only for `transformer_baseline` (other architectures
raise). `profile_freeze.json` pins microbatch/accumulation/backend/precision for
matched runs.

### 3.5 CLI & doctor

`xlm train`/`resume` accept `--precision`, `--attention-backend`,
`--compile`, `--activation-checkpointing`; unresolved backends and unsupported
precision fail with explanations. `xlm doctor` reports BF16 support, probed SDPA
kernels, wheel build, and unsupported-configuration explanations (CPU wheel with
GPUs present, GPU-less CUDA wheel, missing BF16, driver older than wheel build);
stale capability strings were corrected.

## 7. Honest Scope Statements

- **Compile/eager parity is NOT RUN.** CUDA codegen lacks Triton in this wheel and
  CPU Inductor lacks a C++ compiler (`cl`); both parity tests skip with the exact
  reason. The compile mechanism, reporting and refusal paths are implemented and
  tested; parity itself is unverified here.
- **No flash attention in this build.** The cu126 Windows wheel was not compiled
  with flash attention; SDPA runs mem_efficient/math. Throughput figures reflect
  that reality, not flash-attention projections.
- **No live OOM occurred.** Recovery is unit-tested (restart/fork/data rules), not
  battle-tested; matched-run freezes are written but no matched runs executed.
- **Dry-run data is synthetic.** Loader wait, throughput and VRAM reflect
  in-memory random tokens; production-loader figures will differ.
- One worker-isolation defect (shared checkpoint IDs aliasing another model's
  artifacts) was found during the runs, fixed, and the affected measurements
  re-run; bogus artifacts and ledger rows were removed.
