## 2. Implemented Architecture & Components

### 2.1 Objective Subsystem (`src/xlm/objectives/`)
- **`BaseObjective` (`src/xlm/objectives/base.py`)**:
  - Abstract base class inheriting from `nn.Module` to support optional objective-owned trainable parameters.
  - Declares `capabilities`: `loss_protocol` (`token_additive` | `custom_batch`), `supports_microbatching`, `has_auxiliary_parameters`, `requires_hidden_states`.
  - Defines `accumulate_microbatch_gradient`: accumulates gradients scaled by global valid target count $1 / N_{\text{global}}$.
  - Custom exceptions: `InvalidBatchError` (empty / all-masked batch), `UnsupportedBatchingError` (unsupported microbatching for global-batch objectives).
- **`CrossEntropyObjective` (`src/xlm/objectives/cross_entropy.py`)**:
  - Validates already-shifted labels and loss masks without redundant label shifting.
  - Handles padding, BOS, and ignored target positions by masking them out (`loss_mask=0`), while retaining valid EOS targets.
  - **Sentinel Guard**: Safe label indexing via `torch.where(mask_bool, labels, 0)` before loss computation to prevent CUDA/PyTorch gathered out-of-bounds indexing on masked sentinels (e.g. `-100`).
  - Strict invalid batch handling: an all-masked batch raises an explicit `InvalidBatchError` when `allow_empty=False`, and returns clean zero loss without NaN or fabricated perplexity when `allow_empty=True`.
  - Standalone batch loss: normalized by `valid_target_denominator`.
- **`compute_independent_diagnostic_ce` (`src/xlm/objectives/cross_entropy.py`)**:
  - Independent next-token NLL diagnostic computation in stable precision, returning unscaled NLL sum and valid target count independent of the optimized objective.
- **`NoOpObjective` (`src/xlm/objectives/noop.py`)**:
  - Pure pass-through plugin used solely to verify research extensibility without trainer branching. Produces bitwise identical loss and model gradients to baseline CE.
- **`AuxiliaryLearningObjective` (`src/xlm/objectives/auxiliary_fixture.py`)**:
  - Test-only objective with an auxiliary trainable parameter `aux_param` and non-zero analytical gradient.
  - Normalization adheres to token-additive accumulation. Enables testing parameter optimization without weight decay (`weight_decay=0.0`).

### 2.2 Optimizer Subsystem (`src/xlm/optimizers/`)
- **`build_parameter_groups` (`src/xlm/optimizers/base.py`)**:
  - Traverses model and objective named parameters with `remove_duplicate=False`.
  - Deduplicates by `nn.Parameter` object identity in-process.
  - Tied weights (`lm_head.weight <-> embed_tokens.weight`) are grouped exactly once.
  - Resolves decay policy across all aliases prior to assignment: norm parameters (`RMSNorm.weight`) and 1D biases have `weight_decay = 0.0`; embedding decay obeys `decay_embeddings: bool`.
  - Verifies zero parameter omissions and zero duplicate assignments across groups.
- **`ParameterGroupManifest` (`src/xlm/optimizers/base.py`)**:
  - Ordered semantic manifest storing canonical names, aliases, shapes, dtypes, and group hyperparameter options. Avoids persisting runtime `id(p)`.
  - `verify_against`: Strictly verifies semantic identity, parameter names, ordering, and shapes on checkpoint reload.
- **`estimate_optimizer_memory` (`src/xlm/optimizers/base.py`)**:
  - Formula-based optimizer state memory estimation ($2 \times \text{unique\_params} \times 4$ bytes for FP32 AdamW moments). Clearly marked as formula estimate, distinct from allocated memory or peak GPU memory.
- **`create_adamw_optimizer` (`src/xlm/optimizers/adamw.py`)**:
  - Instantiates `torch.optim.AdamW` with Contract C09 hyperparameters: `betas=(0.9, 0.95)`, `eps=1e-8`, `weight_decay=0.1`.
- **`serialize_optimizer_state` & `restore_optimizer_state` (`src/xlm/optimizers/adamw.py`)**:
  - Independent state snapshot serialization and manifest-verified restoration. Rejects reordered or mismatched parameter state dictionaries.
- **`clip_global_gradient_norm` (`src/xlm/optimizers/clipping.py`)**:
  - Global $L_2$ norm clipping evaluated across the unique deduplicated set of model and objective parameters after global normalization.

### 2.3 Learning Rate Schedules (`src/xlm/schedules/`)
- **`WarmupCosineSchedule` (`src/xlm/schedules/cosine.py`)**:
  - Side-effect free queries based on committed valid targets counter.
  - Linear warmup over $W$ targets, cosine decay over $H - W$ targets, and constant minimum ratio $r_{\text{min}}$ beyond horizon $H$.
  - State dictionary and `load_state_dict` strict validation: changing horizon, warmup, base LR, min LR ratio, counter identity, or schedule type on ordinary resume raises an explicit `ValueError`.
- **`ConstantSchedule` (`src/xlm/schedules/constant.py`)**:
  - Constant learning rate fixture schedule.
- **`MODEL_SIZE_LR_ANCHORS` (`src/xlm/schedules/anchors.py`)**:
  - Initial uncalibrated baseline learning rate anchors: 50m ($10^{-3}$), 150m ($6 \times 10^{-4}$), 300m ($3 \times 10^{-4}$), tiny ($10^{-3}$).
