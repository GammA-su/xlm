## Safe reuse and retained mutable state

`tests/runtime_fixture.py` captures immutable canonical inventory bytes once per
pytest worker/session and supplies a newly decoded nested value to each consumer.
Its identity binds lock/project/Python-pin content, extras, producer source,
default site location, interpreter files, platform and dependency-marker inputs,
plus the full real inventory payload. It is a prerequisite for an explicitly
immutable installed environment, not a general production memoizer. A fresh full
inventory at teardown fails the session if that precondition changed.

Only eleven audited queue/report fixture consumers opt in (fifteen fixture captures
across the original complete B selection). Changed contract inputs or explicit
alternate sites invoke the original inventory. Environment mutation, missing
tools, damaged packages, CPU/CUDA refusal, all frozen verification and every CLI
or worker process retain fresh inventories. `--fresh-runtime` disables automatic
queue-fixture reuse. The transient patch exists only inside the original fixture
freeze, ends before admission/execution, and restores the original alias.

Tests prove cached and uncached full plans equal, nested values independent,
lock/project/pin changes bypass, and an explicit private authored site detects
same-size package-file mutation even with restored mtime. No production function
is changed. These tests do not claim that authored package metadata proves live
backend compatibility; the installed optional gate supplies separate real-package
evidence.

P30's frozen-input byte seed remains intact. Consumers still materialize private
snapshot directories, plans, queues, ledgers, cursors, homes and outputs. Admission
and integrity verification remain real. Grouping keeps seed consumers together,
while independent custom-worker and provenance workflows can overlap. This new
cache shares no mutable execution output, model, tokenizer or queue across tests.

Polling audit found bounded condition checks (typically 20–100 ms). Long sleeps
in crash targets deliberately keep owned processes alive until termination.
No safe fixed-wait removal was justified, so polling and production timing
semantics are unchanged. Real kill, rename/fsync, locks, process ownership and
recovery assertions remain intact.

domains. One controller uses four workers and `--dist=loadgroup`; no nested
controller, auto worker count or global addopts is introduced. Per-test homes and
temporary directories are private; local servers bind ephemeral loopback ports;
kill tests act on owned children. Installed dependencies are read-only.
Process-pool cases share one group to bound fan-out. Queue consumers share a group
for prerequisite locality. Frozen admission, custom workers and provenance have
independent state. Recovery cases remain together. Independent CLI campaigns may
overlap after this resource audit, not merely because their files differ.

`-n 0`. Unknown serial tests default to core/exclusive. Unknown optional tests
are refused under parallel execution until audited. Wrong schedulers and exclusive

aggregate rather than a missing group's apparent success. Both negative probes
were verified to exit 2 with a clear diagnostic. Initial guard experiments that
