## 2. Implemented Architecture & Components

### 2.1 Deterministic Data Batching & Causal Shifting (`src/xlm/training/data.py`)
- **`DataCursorState`**:
  - Deterministic serialization of reader/stream token offsets, document indices, document exposure counts, epoch counts, and carryover context tokens.
- **`TrainingBatcher`**:
  - **Context Carryover**: Sequences carry over context token across adjacent windows (window $k$ token $T$ becomes window $k+1$ token $0$).
  - **Causal Target Shifting**: Shifted strictly as `input_ids = window[:-1]`, `labels = window[1:]`.
  - **Target Masking**: Excludes padding and BOS (`loss_mask=0`), retains valid EOS tokens (`loss_mask=1`).
  - **Exact Budget Completion**: Safely truncates updates to exact remaining budget (e.g. $8 + 8 + 1$).
  - **Untrained Suffix Preservation**: When a partial update commits $R < N_{\text{valid}}$ targets, the last committed target index $k^*$ preserves the context carryover token `labels[k*]` and adjusts the stream offset (`stream_start + k* + 1`), ensuring zero duplicate and zero omitted token exposures upon subsequent resumption.
  - **Microbatch Sequence Chunking**: Sequences within a step are partitioned into microbatches without splitting context sequences.
  - **Exhaustion Policies**: Strictly rejects silent truncation; supports `"stop"` and `"repeat_bounded"` with exposure limits.

### 2.2 Atomic Checkpoint Management (`src/xlm/training/checkpoint.py`)
- **`CheckpointMetadata`**:
  - Records checkpoint ID, run ID, step, committed/processed valid targets, plan ID, schema version, timestamp, parent lineage (`parent_checkpoint_id`, `parent_plan_id`), and individual file SHA-256 checksums.
- **`CheckpointManager`**:
  - Built directly on top of Milestone P01 `ArtifactStore`, `RunLedger`, and `ArtifactPaths`.
  - **Two-Stage Atomic Publication**: Writes weights, optimizer state, schedule state, batcher state, RNG state, and metadata to a local temporary staging directory, computes cryptographic SHA-256 checksums, and publishes atomically via `ArtifactStore.publish_dir`.
  - **Tied-Weight Validation & Restoration**: Verifies bitwise equality of tied weights (`embed_tokens.weight` and `lm_head.weight`) before save and after load, explicitly restoring PyTorch `model.lm_head.weight = model.embed_tokens.weight` object identity.
  - **RNG State Restoration**: Restores Python `random`, PyTorch CPU, and PyTorch CUDA generator states bitwise.
  - **Plan Compatibility & Lineage**: Enforces matching `expected_plan_id` on ordinary resume; supports branched exploration via `is_fork=True` with explicit parent lineage recording.

### 2.3 Training Loop & Fault Guards (`src/xlm/training/trainer.py`)
- **`Trainer`**:
  - CPU and CUDA training execution with FP32 and BF16/FP16 mixed precision support.
  - **Microbatch Gradient Accumulation**: Accumulates gradients across uneven microbatches scaled by $1 / N_{\text{global}}$.
  - **Global Gradient Clipping**: Clips global $L_2$ norm evaluated across deduplicated unique parameters via `clip_global_gradient_norm`.
  - **Fault Guards**: Checks for non-finite loss and non-finite gradient norms; aborts immediately with `NonFiniteGradientError` without corrupting optimizer state or checkpointing invalid weights.
  - **Cooperative Interruption**: Intercepts `SIGINT` and `SIGTERM` signals, setting `_stop_requested` to safely finish the current optimizer step, save a clean checkpoint, and exit gracefully with termination reason `"interrupted"`.
  - **Structured History**: Collects immutable `TrainingStepMetrics` and returns complete `TrainingSummary`.

### 2.4 CLI Training, Resume, Run Inspection & Demo Commands (`src/xlm/cli/`)
- **`xlm train` (`src/xlm/cli/train_cmd.py`)**:
  - Loads and composes experiment plans/recipes via `ConfigComposer`, validates schemas, and executes training with configurable `--device`, `--max-targets`, `--max-seconds`, and `--dry-run`.
- **`xlm resume` (`src/xlm/cli/train_cmd.py`)**:
  - Resumes execution from existing checkpoint path. Supports `--fork` to branch runs and `--budget` to extend the training horizon.
- **`xlm run inspect` (`src/xlm/cli/train_cmd.py`)**:
  - Lightweight, metadata-only command that inspects checkpoint directories, run directories, and manifest files without importing PyTorch or initializing CUDA.
- **`xlm demo` (`src/xlm/cli/demo_cmd.py`)**:
  - Self-contained offline vertical slice demonstration: synthetic canonical documents -> ByteTokenizer -> token shard -> tiny TransformerBaseline training to 100 targets -> checkpoint at natural optimizer boundary -> fresh component reconstruction -> reload -> resume to 200 targets.

### 2.5 Windows SQLite File Locking Resolution (`src/xlm/artifacts/ledger.py`)
- Refactored `_get_connection` into a contextmanager that guarantees `conn.close()` is executed in a `finally:` block, preventing file descriptor leaks and `PermissionError: [WinError 32]` on Windows when cleaning temporary directories.
