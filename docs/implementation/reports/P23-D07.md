## 2. Root cause

`src/xlm/export/writer.py::_expand_shared_tensors`, verbatim from `bd01e60`:

```python
"""Clone storage-shared tensors so safetensors accepts the bundle. ..."""
pointer = value.data_ptr() if hasattr(value, "data_ptr") else id(value)
if pointer in seen:
    expanded[key] = value.clone()
```

`state_dict()` lists every alias name, all pointing at one tensor. The safe
format refuses to write one storage twice, so the writer **cloned** the second
alias. Both names then carried a full payload.

Three further consequences, all fixed here:

* deduplication keyed on `data_ptr()`, which is arbitrary shared storage rather
  than a declared tie, so an unsupported view was silently cloned into an
  ordinary tensor;
* the manifest's `tied_mapping` was a group→list with no canonical/alias
  distinction, so nothing said which name held the payload;
* the loader hardcoded `embed_tokens.weight`/`lm_head.weight`, putting
  Transformer-specific names inside the generic export path.

The *accounting* was already honest — `parameters_deployed` reported 98,880
correctly — which is precisely why fresh-process numerical parity never
established the C08 single-copy storage requirement.

## 4. The repair

### 4.1 `src/xlm/models/aliases.py` (new)

Ties are resolved from **declared model relationships**: `nn.Parameter` object
identity over `named_parameters(remove_duplicate=False)`, the same basis
`count_model_parameters` already uses, never from value or hash equality.

`assert_complete_alias` then requires a *complete same-tensor alias* — identical
shape, dtype, `data_ptr`, `storage_offset`, total storage bytes and contiguity.
A transpose, a narrow or a zero-offset slice can share a first element while
denoting different data, so equal `data_ptr` alone is explicitly not accepted.
Slices, offsets, transposes and reinterpreting views are **refused**, not
flattened into ordinary ties. A general arbitrary-view serialization engine is
deliberately out of scope, as permitted.

Parameters and *persistent* buffers are enumerated with their roles; a buffer
sharing object identity with a parameter is refused, so stored state and
deployed parameters cannot be interchanged. The reference Transformer's RoPE
caches are `persistent=False` and never reach a bundle.

`validate_alias_map` rejects dangling targets, self-aliases, alias chains (hence
cycles) and any alias that also carries its own payload.
`restore_alias_identity` / `verify_alias_identity` resolve dotted names to the
owning submodule generically — **no architecture-specific tensor name appears in
the writer or the loader**.

### 4.2 `src/xlm/models/base.py`

One new method, `BaseModel.tied_parameter_aliases()`, with a default body
delegating to `resolve_tied_aliases(self)`. Overridable; no existing plugin
breaks. This is the whole registered model-alias interface change.

### 4.3 `src/xlm/export/writer.py`

`_expand_shared_tensors` is replaced by `build_single_copy_payload`, which emits
**canonical names only** — alias names carry no payload. Undeclared shared
storage now raises `ExportError` instead of being cloned. The canonical name is
the first in `named_parameters` order, so it is deterministic per architecture.
`_payload_inventory` reads the written container back so the manifest's reported
inventory describes what the bundle actually contains.

### 4.4 `src/xlm/export/manifest.py`

`EXPORT_FORMAT_VERSION = "2"`, with `SUPPORTED_EXPORT_FORMATS = ("1", "2")`. New
fields: `alias_map` (alias → canonical), `alias_schema_version`,
`storage_layout` (`single_copy` | `duplicated_legacy`), `serialized_tensor_entries`
and `serialized_payload_bytes`. A manifest lacking `storage_layout` is read as
`duplicated_legacy` — absence is never read as a single-copy claim. A v1 bundle
declaring `single_copy` is refused. Checks run format → serializer → layout, so
the most fundamental refusal surfaces first.

### 4.5 `src/xlm/export/loader.py`

v2 validates the alias map against the payload and against the constructed
model's expected shapes/dtypes, materializes each alias as **the same tensor
object** as its target so `load_state_dict` stays strict with every key present,
then re-establishes Parameter identity generically. No blanket `strict=False`,
no pickle, no remote code.

Identity is **re-verified after `.to(device)` and dtype conversion** and
re-established if conversion replaced the objects — verified rather than assumed,
as required.

## 7. D01 publication integration

Added caller-side only, through the existing public
`ArtifactStore.publish_artifact`. No second artifact store, no change to the
store's implementation, semantics, ledger or shared schemas.

* `producer_code_hash` — digest of the exporter's own sources
  (`writer`, `loader`, `manifest`, `aliases`).
* `dependency_hash` — python, torch, safetensors versions.
* `resolved_config_hash` — `export_representation_identity`: format version,
  alias schema, storage layout, serializer, alias map, precision, config and
  tokenizer hashes. This is the **serialized representation** identity, kept
  separate from the checkpoint's training provenance: re-exporting unchanged
  weights under a new layout is a new representation of the same model.
* `cosmetic_metadata` — the wall-clock stamp only.

**Bundle determinism.** v2 `export_manifest.json` no longer carries
`created_at`. A timestamp inside the bundle would make two identical exports
differ byte-for-byte and turn verified reuse into a spurious conflict. The stamp
moves to D01 `cosmetic_metadata`, which the store already excludes from
equivalence. Unchanged files keep their hashes: `config.json` and the tokenizer
are byte-identical to before; only `model.safetensors` and
`export_manifest.json` change, and they change because their content genuinely
changed.

Publication is **opt-in** (`publish=True`, `xlm export --publish`). A bundle
remains standalone either way, proven by loading a copied bundle after deleting
the store and unsetting `XLM_HOME`.

## 10. Supported and unsupported

### Supported

* Complete same-tensor ties between parameters of one registered architecture,
  stored once and rebuilt from explicit alias metadata.
* Persistent buffers, stored under their own names by declared role.
* Legacy v1 bundles: loaded after shape, dtype and exact-bit validation,
  reported as `duplicated_legacy`, never rewritten or relabelled.
* CPU float32 loads; CUDA float16/bfloat16 loads as before.

### Unsupported — refused loudly, never silently transformed

* Slices, offsets, transposes and other partial or reinterpreting shared-storage
  views.
* Distinct objects sharing storage without sharing object identity.
* A tie between a parameter and a buffer.
* Alias chains and cycles.
* A v2 bundle in which the alias also carries its own payload.
* A v1 bundle claiming `single_copy`.

### Not migrated

No automatic migration or re-export of existing v1 bundles. A separately
requested re-export produces a new v2 artifact under a new representation
identity.

## 12. Shared-interface considerations for integration

1. **`BaseModel.tied_parameter_aliases()`** is a new method with a default
   implementation. Any model class outside this branch inherits working
   behaviour; an architecture that ties by some other mechanism should override
   it and must still return complete same-tensor aliases.
2. **Export format v2.** Bundles written before this change still load and are
   reported `duplicated_legacy`. Anything that pinned
   `EXPORT_FORMAT_VERSION == "1"` should move to `SUPPORTED_EXPORT_FORMATS`.
3. **`export_manifest.json` no longer carries `created_at`** in v2 (§7). A
   consumer reading that field from a v2 bundle should read the D01 artifact's
   cosmetic metadata instead.
4. **`tied_mapping` group keys changed** from the Transformer-specific
   `tied_lm_head` to a generic `tied_<canonical_name>`. `alias_map` is the
   contract; `tied_mapping` is the human-readable view.
5. **New artifact kind `exports`** appears in the store when `--publish` is
   used. No store code changed; the kind is free-form and not reserved.
6. **`xlm export` gained `--publish`.** `cli/main.py` registration is untouched.
7. Not touched: `comparison/bootstrap.py` or any D08 analysis code, acquisition,
   preparation, source transport, the trainer, frozen-worker execution, generic
   artifact-store behaviour, evaluation task definitions or scoring semantics.
