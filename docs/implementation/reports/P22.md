## 3. Implemented Architecture

### 3.1 Staged preparation (`prepare/`, `xlm prepare`)

Configs declare exact stage argv with `{repo}/{home}/{output_root}` variables
(unknown variables fail closed), per-stage approvals, verified outputs, watched
inputs and downstream invalidations. `--plan-only` reports
blocked/stale/pending/reusable/check-only per stage with reasons and counts.
Execution requires `--authorize` (recorded), reuses verified stages, resumes
partial ones, rebuilds only with recorded `--force`, writes state after every
stage, and runs each command through this interpreter. A bounded `local_copy`
kind covers offline fetching; live fetch stays approval-gated.

### 3.2 Recipe set and validation

New validated configs: `tiny_demo` experiment, five comparison recipes (new
`comparison_recipe` kind with track checking), `confirm_multiseed`,
`factorial_demo` and staged `staged_50m_150m_300m` campaigns, plus the
`offline_toy` prepare config and toy mixture. `xlm config validate` now
dispatches model/mixture/comparison/campaign/prepare/view-registry kinds.
Drafts validate as drafts and fail executable mode; the recipes README example
commands were rewritten to the real CLI and are executed by tests.

### 3.3 Campaign staging and cost basis

The staged campaign runs 50M screens (128M, shared 1B horizon), 512M/1B/3B
validations at 150M, and 6B confirmation at 300M across six mixtures (60
trials), with later rounds gated on explicit selection. `campaign plan
--throughput lo,hi` prices from measured profiles; without it the basis stays
`unmeasured` with a "measurement required" note.

### 3.4 Maintenance and runbooks

`xlm maintenance` lists scratch/tmp files by default and removes only those,
bounded by `--max-bytes`, refusing over-cap removals. `docs/runbooks/`
documents install through operator finals on Windows and Linux with implemented
flags, disk locations, reachability cleanup, safe cancellation, a failure
table, portability notes and the unverified inventory.
