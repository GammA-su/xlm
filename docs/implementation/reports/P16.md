## 3. Implemented Architecture

### 3.1 Code snapshots (`experiments/snapshot.py`)

Capture set = `src/`, `recipes/`, `manifests/`, `pyproject.toml`, `uv.lock`,
`.python-version` (data, venvs, caches excluded by construction). Untracked files
outside the includes enter only under the plugin/recipe allowlist. Secret-like
basenames fail the whole capture loudly. Output is a copied tree plus a sha256
manifest and code hash; the runner re-verifies before launch and blocks on any
divergence.

### 3.2 Authorization (`experiments/authorization.py`)

Tickets bind one plan hash to explicit target/time/disk/GPU limits. Without a
ticket only the C13 smoke caps apply (200k targets, 600 s, 1 GPU, 2 GiB); larger
runs are refused naming the exceeded cap. Mismatched hashes are always refused.

### 3.3 Plan resolution (`experiments/plans.py`)

Drafts compose through the existing composer and validate against the frozen P01
schemas. Null/unresolved artifacts, non-developer tiers, missing cadences and
unmeasured cost are approval blockers, never defaults. Seeds, code hash, lockfile
hash, artifacts, track, horizon tag and exposure all feed the plan hash.
Horizon tagging (`continuation_prefix` vs `standalone`) keeps the two run kinds
incomparable. `extend_plan_budget` forks with parent lineage; non-fork resume
past the saved horizon is refused in `xlm resume`.

### 3.4 Sweeps (`experiments/sweeps.py`)

Explicit lists, deterministic cartesian grids, seeded Dirichlet-like proposals
and coarse simplex lattices (largest-remainder repair keeps exact sums), all
under a trial cap. No background optimizer exists.

### 3.5 Campaigns (`experiments/campaigns.py`)

`data_search.yaml` expands to 54 trials (6 mixtures × rounds/seeds) with per-trial
complete configs, shared-horizon continuation tags for round 0 and matched
standalone horizons later. Later rounds stay blocked until `record_selection`
names them. Campaign tickets bind the campaign hash and total; over-budget
sweeps are refused pre-submit.

### 3.6 Queue (`experiments/queue.py`)

New `queue_jobs`/`queue_attempts` tables (no ledger version bump). Submit
deduplicates by plan hash (plus job-ID and ledger-PK backstops). One GPU lease
per device via lock-guarded files with stale-holder theft recorded. CPU
preparation runs in a bounded pool. The generic runner verifies the snapshot,
matches plan/job device families, leases, heartbeats, honors cancel flags,
records attempts with failure evidence, and releases the lease. Crash recovery
marks stale RUNNING jobs INTERRUPTED and requeues only within retry policy, and
is idempotent.

### 3.7 CLI

`xlm experiment plan|authorize|submit`, `xlm queue run|status|cancel`,
`xlm campaign plan`. Planning/display commands need no torch.

## 6. Honest Scope Statements

- **No billion-token trials ran.** Campaign trials are complete plans, not
  executions; toy runs use tiny synthetic budgets on CPU.
- **Evaluation cadence is predeclared, not queue-executed.** Checkpoint cadence
  is enforced by the runner; suite evaluation stays a separate `xlm evaluate`
  invocation.
- **No live GPU lease contention occurred.** Lease exclusivity, staleness and
  busy-refusal are unit-tested without hardware.
- Secret patterns are basename heuristics (`*api*token*` etc.), not a
  certification; `tokenizer_*` filenames were deliberately excluded after a
  fail-closed misfire during development.
